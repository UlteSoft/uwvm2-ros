# Numeric GC code-generation contracts

The fixtures check exact i64, f64 (including signaling NaN and negative zero) and v128 bits, null and index traps, canonical foreign-module ownership, subtype fallback, aliases, hash-bucket collisions and live collection. The existing scalar and packed suites cover the smaller numeric types. Borrow-boundary fixtures exercise local reassignment, branches, loops, calls, allocations, reference-valued helpers, changing array indices and late publication. Calls that collect retain the original object and verify it after collection. Cross-function fixtures exercise subtype fallback for packed i8/i16 signed and unsigned reads, i32 overflow and exact f32 payload bits. Root fixtures keep the same complete reference in locals, operands and arguments across allocation pressure, and separately keep an older operand live after rebinding its local; both values must survive and retain their distinct contents.

The private-crosscall fixtures exercise closed-caller specialization through aliases, repeated calls and allocation pressure, together with null and out-of-bounds traps. Late publication, publication by a callee, an ineligible target in unreachable code, a looping callee and an already-shared object must keep the conservative path. The allocation-boundaries case keeps an array alive while 65,536 independent allocations occur between leaf calls; real collector counters must accompany any claim that collection was exercised. The manifest currently contains 83 semantic cases.

Private-call ABI fixtures exceed the integer, floating-point and reference argument register counts and exercise vectors, mixed aggregate returns and exact signaling-NaN bits. They distinguish the specialized entry from the unchanged public ABI on all five targets. The outlined-subtype case deliberately fails the exact-layout guard with a legal derived array, then requires the checked helper to return normally and increment exactly once per call. Null and bounds fixtures also exercise failure delivery from checked fallbacks.

Machine-code qualification is separate from outcome testing. Inspect each target's actual generated object: admitted callers must use the private clone, shared or ineligible callers must retain the public entry, and generic mutation must retain its lock. For the private loop, root stores may be coalesced outside the loop only while every allocation and unknown call retains its root boundary. Check x86_64, i686, AArch64, ARM soft-float and ARM hard-float separately; a cross-build or an IR dump alone does not establish the emitted instructions. Inspect cold helpers and their unwind metadata separately from the fast path; retained parent Wasm frames and wrapper filtering must also survive signed-cache reload.

Run both the interpreter and LLVM JIT with ../run_numeric_codegen.py. The runner requires an existing VM and a GC-capable assembler, writes all outputs to the explicit output directory, accepts an existing QEMU argv prefix, and never installs tools. The wat-to-wasm assembler style accepts a converter with positional input/output arguments. The entry field is a local-defined function index, not an import-inclusive index. foreign-provider.wat is a real preloaded Wasm module.

These are regression contracts, not a claim of exhaustive Core 3 conformance. The separate Core 3 specification suite remains necessary. They deliberately isolate standard GC semantics from the nonstandard memory-tag extension.
