This producer runs genuine Python code in pinned CPython3.14.8 compiled to a WASI Preview1 command. It is an interpreter port; freezing embeds CPython code objects and does not turn the kernel into hand-translated C or native Python AOT code.

Official inputs are fixed in `versions.json`. The [CPython3.14.8 release](https://www.python.org/downloads/release/python-3148/) publishes the source XZ SHA. Its [WASI build helper](https://github.com/python/cpython/blob/v3.14.8/Tools/wasm/wasi/__main__.py) selects SDK24 and wasm32-wasip1. The helper configures unchanged source; explicit `make -j2/4` bounds compilation rather than relying on the helper's automatic CPU count. All extraction, bytecode generation, native/WASI builds and execution must run in the existing SSH Linux64GiB Docker cgroup. Local static acquisition of official archives is allowed when Linux network transfer fails; Linux rechecks hashes before extracting them.

`build.py --work /absolute/fresh/work --wasmtime /absolute/wasmtime --jobs 4 --cpus 4,5,6,7` builds a matching native CPython, stock `python.wasm`, and three native/WASI application pairs. Optional `--input-dir /absolute/static-inputs` reuses transferred official archives. A failed attempt retains its logs; `--resume` preserves the previous build receipt and reuses only matching successful, retired command receipts. Do not resume in somebody else's work directory. `linux_control.py` retains process pidfds, starts commands behind an authentication barrier, and checks cgroup placement, core0, RSS, shared memory events and disk reserves. It does not create or resize cgroups.

The base applications use an isolated embedding launcher with an explicitly empty module search path. Frozen encodings/aliases/UTF8/ascii/latin1 plus actual fixture modules supplement CPython's existing frozen startup modules. The launcher explicitly disables site/bytecode-file writes and enables frozen stdlib modules, configures UTF8 before argv decoding, and keeps fixture assertions enabled. Startup module/source/header hashes are recorded. These applications need no external runtime files or directory preopens **once actual native/Wasmtime qualification passes**. The unmodified stock interpreter remains available separately, and its ordinary startup still needs stdlib assets; `-c` alone does not remove that dependency. `build-receipt.json` inventories the pinned Lib sources for a separately configured filesystem bundle. No whole-host root mount is the default.

`hll_common.py` tests class inheritance, list operations, dictionaries, Unicode/UTF8, chained exceptions/finally, argv/environment, bytes/bytearray/memoryview ownership and actual CPython cycle collection. Its deterministic64-element kernel uses integer arithmetic and an accumulator class. `checksum_oracle.py` is an independent scalar formulation. `references.py --build WORK --out FRESH --wasmtime PATH` executes original source with matching native CPython, native embedded applications and official Wasmtime using identical Wasm bytes and no preopens. It validates empty/UTF8 argv, zero/one/multiple explicit env entries, bad iteration inputs, timed outputs and real blocking READY/G/DONE/D gates. Reference timing is for correctness/calibration, not the final matched engine benchmark.

`timed.py` excludes semantics,100-round warmup, array construction and clock warmup from the reported monotonic nanoseconds. `profile.py` does the same, emits exact stderr READY before reading byteG, emits DONE after stopping the timer, waits for byteD, and only then prints stable semantics/checksum and timer output. Neither wait is inside the kernel timer. `write_manifests.py` refuses to publish functional/timed/gated manifests before build/reference reports pass and all artifact hashes match. Functional DBG is delegated to the common matrix; performance calibration and quiet hardware collection belong to the parent task.

Debug scope is Wasm/native CPython entry, step, backtrace, breakpoint, restart and guest output. DWARF describes CPython C code. There is no current Python-source/locals bridge, and this producer does not claim one. [SDK-extension.md](SDK-extension.md) describes the optional static inittab hook for an SDK-owned C extension in the same Wasm; `_ctypes`/libffi and dynamic extensions are not required by the base application. [research.md](research.md) records the independent official-source review and ROS ABI boundary.

See [qualification.md](qualification.md) for real artifact identities, immutable local evidence, exact scope and pending parent-matrix work. Source files alone are not PASS evidence. [SDK-reuse.md](SDK-reuse.md) documents the retained native/WASI build tree and static ROS-extension hook; full stdlib is a separate deployment contract.

The stock CLI requires an explicit standard-library bundle. Use `stock_stdlib.py`
and `stock_stdlib_probe.py` with the selected producer and runtime inputs.
Python trace/locals checks and instruction-level Wasm workflows do not provide
a UWVM Python-source debugger bridge. Functional checks and performance
measurements need separate current execution results.
