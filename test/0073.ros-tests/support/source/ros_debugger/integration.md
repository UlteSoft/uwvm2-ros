# Actual Runtime integration entry

`integration_runtime.py` is an executable preparation of six real integration
jobs. Its source has not been run by the implementing agents. Root executes
the six closed rows in `integration-jobs.json`, serially under its current
64 GiB/swap-zero parent lease and private mount namespace. The existing
interpreter/core/SDK/original-regression acceptance remains mandatory.

## Prerequisites and exact launch interface

Build a **fresh LLVM-full** ROS1, ROS2 and dual Runtime with real LLVM/compiler,
stdlib, headers, libraries/archives and response-file closure. The original
four interpreter products remain separate. `prepare_debug_jit_mode()` requires
LLVM-full/native threads; this entry does not bypass or weaken that guard.
The per-profile physical report follows `runtime-build.schema.json`. The
integration consumer checks its exact current frozen source/MF, original
compile/object/full-MD/link association and reopened seven-field pins. It
accepts a dual product for either single-backend Guest too, but the closed
recommended matrix uses the three actual profile builds. A build PASS is not
an integration PASS.

The initial Worker adapter is native Linux x86_64 ELF62. Its actual stopped
kernel executable and retained birth are checked by the existing Host role
proof. It is **not reported as ARM execution**. The existing Lane separately
qualifies and maps the two ARM SDK Gateway/peer products under the selected
QEMU, preserving full original compiler dependencies and SDK inventories.
A future matching-target Worker requires its own real mapping adapter; this
script does not guess or relabel that target. All Root-supplied paths are
explicit, including the native SDK QEMU configuration. The Runtime does not
inherit that QEMU prefix or an ambient loader/ROS environment.

After native SDK peers are prepared and the Runtime reports are available,
Root expands the exact `argv_template` in `integration-jobs.json`. In shell
form for a single row:

```
python3 -B "$SOURCE/test/0073.ros-tests/support/source/ros_debugger/integration_runtime.py" \
  --source "$SOURCE" --manifest "$MANIFEST" --sdk-workspace "$DERIVED_SDK" \
  --out "$FRESH_JOB_OUT" --qemu "$SDK_QEMU" --binfmt-evidence "$LIVE_LEASE" \
  --container-started-at "$CURRENT_STARTED_AT" \
  --worker "$LLVM_RUNTIME" --runtime-build-report "$LLVM_PROFILE_REPORT" \
  --worker-config "$SDK_QEMU_CONFIG" \
  --ros1-gateway "$ROS1_GATEWAY" --ros1-gateway-report "$STRICT1_REPORT" \
  --ros2-gateway "$ROS2_GATEWAY" --ros2-gateway-report "$STRICT2_REPORT" \
  --prepared-native "$SDK_PEER_PREPARE_REPORT" --wat2wasm "$WAT2WASM" \
  --version dual --mode retained --native-step required
```

Both Gateway/report path pairs remain explicit common inputs even for a
single-backend row; only selected versions are started. Output must be fresh.
The current native peer context is fixed to the existing SDK contract:
loopback Master11384, ROS2 domain205, `/uwvm_sdk_relay`, exact pub/sub String
payloads and explicit `pub`/`sub` grants. Retained mode additionally grants an
`events` observer for metadata-only `resource-closed`. This explicitly preserves
the existing legacy reply consumer: it does not create a second data consumer
or activate/consume that Source queue. Default-deny mode has
**no ROS aliases**. Basic stdout and process exit are the only WASI imports;
there is no inherited environment, random, clock or socket permission.

## Real identity, authenticated console and causal sequence

The parent creates a private `SOCK_SEQPACKET` pair. Only the child endpoint is
inherited by the actual Runtime through `--debug-jit-control-fd`; the other
endpoint stays with the retained Root launcher. The production Runtime
authenticates Linux credentials and the launcher's pidfd on every command.
The driver also checks returned Runtime PID/UID/GID and bounded packet/ancillary
shape. No listener, arbitrary attach, fake Host caller or replacement snapshot
callback exists. Guest stdin/stdout are distinct from this control endpoint.
The inherited descriptor number is process-owner setup metadata, never a Guest
ROS permission or a printed secret token.

The actual Runtime is compiled/adopted before starting a native peer's finite
60-second exchange. The peer constructor's cooperative OS stop, current mapping
and I gate are proved through the original native lane. A PID-preserving shell
reserves the real Runtime PID before the Gateway is configured, so production
`SO_PEERCRED` and Gateway Worker pidfd checks apply to the actual principal.

`integration_guest.py` generates a real-import Wasm application. It checks an
ungranted alias returns13 while protected output/length bytes stay unchanged.
The retained mode creates real endpoints and performs the existing independent
native String exchange. It then closes the watched Source. Production Host
retirement creates one actual local64B `resource-closed` record. The Guest
waits in an ordinary Wasm safe-point loop while that record remains queued.
It does not park inside a blocking WASI import or fabricate a pause flag.

The parent asks the real controller to pause. It reads the actual thread and
module labels from `status`. The nine `info ros` selectors and `trace ros`
are issued through the same authenticated console. Each response must be
available and unchanged on repeated reads, and another complete pass must
still equal the first. This binds the stored quota/audit/queue/trace state over
the whole observation window. Queue rows must show the actual retired observer,
depth1, bytes64, dequeued0 and delivered0. Default-deny mode must show no
capability or queue row, and native peer absence checks prove zero Gateway
pub/sub endpoints and zero Guest-induced messages. The explicitly initialized
Gateway and independent peer nodes are setup baselines, not claimed absent.
Real trace rows must identify the actual `main` module and
nonzero Runtime generation; a mathematical DTO provider cannot satisfy this.
The actual owned Gateway stdout/stderr audit streams must also be byte/inode
identical across that window. Those historical window pins are not placed in
the immutable-input set: later Guest cleanup may append legitimate audit
records. The final complete raw stream pins remain in the Lane command rows;
the retained prefix length/SHA lets a reviewer replay the window boundary.

Only separately recorded existing `set wasm memory MODULE MEMORY THREAD
OFFSET bytes HEX` commands advance byte2048 in the application's own memory.
This is an explicit debugger test-control action. It does not occur inside the
read-only observation window and is not attributed to a ROS query. No numeric
module ID is inferred from the ROS registry: the ID for this ordinary memory
command comes from the controller's actual stopped thread roster.

After resuming, ROS queries must refuse while running. A later genuine pause
has a new stop label, and a query carrying the actual old label must report
stale stop without invoking the snapshot. On supported LLVM-full targets,
`--native-step required` performs a real `step asm`, verifies that a native
instruction stop refuses ROS observation, then restores a real Wasm cooperative
step. The explicit `not-applicable` option records
`NOT_APPLICABLE_SELECTED_BACKEND` and no native-step acceptance. It must not
replace a required row. The current supported x86_64 matrix selects `required`.

Finally the Guest is resumed and must consume the **same** retained record:
capacity1 returns90, the full copy validates magic/version/backend/kind/flags,
zero error/correlation/body, exact Source handle, sequence1 and nonzero public
instance/session header fields. The next poll must return11 with untouched
sentinels. Only then does it close its remaining handles and exit0. Independent
native peers check exact payload counts, no excess effects and a bounded quiet
window after Guest exit. A normal Gateway0 is accepted only after its retained
Worker has exited0; early retirement fails.

## Reports and limits

The existing Lane retains current source/SDK/input/product pins, mapped native
roles, Host Runtime executable proof, actual command/gate logs,64GiB/swap0,
same-incarnation/ancestor-OOM evidence and owned process/mount/socket cleanup.
The report's `console_actions` contains actual commands and copied replies;
`same_stop_observation` binds its genuine stop and exact repeat checks;
`independent_native_effects` contains each closed native marker transcript.
`new_tests_executed` becomes true only after real Guest/native completion.
Exceptions retain FAIL and cleanup raw evidence. No old report supplies PASS.

The native observer detects exact application-message effects; the combination
of unchanged Gateway audit streams, real Host-call trace and stored state plus the production source
contract establishes that diagnostic queries issued no native RPC. This is
not a claim to trace every background DDS graph exchange or measure total DDS
memory. Retained audit **counts** are compared; audit bodies and security
credentials are never printed or copied into diagnostic responses. This Linux
entry does not replace macOS/Windows transport acceptance, the ROS-off module
probe or the fixed component tests described in `README.md`.
