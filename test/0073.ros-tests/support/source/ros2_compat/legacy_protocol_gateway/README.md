# Real legacy ROS2 protocol Gateway witness

This explicitly selected trusted-process witness connects an actual production
`uwvm-ros2-gateway` executable to a separately running original ROS2 SDK peer.
It complements the installed-source proof and CDR conversion contracts. Its
client uses the production Unix IPC implementation directly; it is not a Wasm
Guest or a replacement for Runtime permission tests.

The owned `uwvm_source_proof_msgs` package must first be generated by the actual
installed ROSIDL tools. Export and bind the complete installed Message, Service
and Action proof using
[the explicit legacy protocol workflow](../../../../../../sdk/origin/robots/industrial/pre_rihs/PROTOCOLS.md).
Never provide a fabricated feature header, substitute a guessed type identity,
or expose an unproved interface through an automatic fallback.

## Containment and build

The trusted external owner must establish containment before starting any ROS
actor: a hard memory cgroup, zero swap, bounded temporary storage, finite process
and CPU limits, a private network namespace with only an enabled loopback
interface, and deterministic process/mount teardown. Preserve the actual source,
SDK, generated package, provider, executable and dependency hashes. The optional
`loopback.xml` selects the UDPv4 transport described by the
[Fast DDS 2.6 documentation](https://fast-dds.docs.eprosima.com/en/v2.6.11/fastdds/transport/whitelist.html).
The network namespace independently prevents access to a physical robot network.

Configure inside that environment, using absolute paths from the same coherent
source/proof and installed package selection:

```sh
cmake -S test/0073.ros-tests/support/source/ros2_compat/legacy_protocol_gateway -B /owned/witness-build \
  -DUWVM_BUILD_LEGACY_PROTOCOL_GATEWAY_WITNESS=ON \
  -DCMAKE_PREFIX_PATH='/owned/native/uwvm_source_proof_msgs;/opt/ros/humble' \
  -DCMAKE_CXX_FLAGS='-O1 -g0 -MD -I/owned/rebound/protocol/generated' \
  -DUWVM_ROS_CUSTOM_REGISTRY_HEADER=/owned/rebound/protocol/generated/manifest.hpp \
  -DUWVM_ROS_CUSTOM_ROS2_HEADER=/owned/proofs/protocol/native_source_provider.hpp
cmake --build /owned/witness-build -- -j1
```

The Gateway must separately be built from that selection with its real SDK
compile/link probes. The witness does not enable a lifecycle feature by defining
a macro. It is a C++17 native SDK test; bounded diagnostics and configuration I/O
use the existing production native compatibility adapter.

## Two original-process checkpoints

The owner launches this exact argument vector with a writable stdin pipe:

```text
/owned/witness-build/uwvm-legacy-protocol-gateway
  --trusted-native-fixture
  /owned/gateway-build/uwvm-ros2-gateway
  /owned/live
```

At the initial `SIGSTOP`, inspect the actual original child PID, parent,
starttime, executable, memory cgroup and network namespace. Create a mode `0700`
directory and call `configuration.prepare(directory, pid, uid, native_export,
registry, socket_directory="/owned/live")` from the exact captured
`configuration.py` when the actors use that chroot-visible socket directory.
The generated mode `0400`
files have zero grants and eleven explicit fixture grants respectively. They
bind the observed process PID; a socket path or matching UID alone is
insufficient. Resume with `SIGCONT` and write exactly one `I` byte to stdin.

At the second `SIGSTOP`, the actual protocol operations have completed and the
original production Gateway remains a direct child. Capture both actual actors'
identities and kernel `map_files` descriptors, associate them with their real
opened SDK aliases, and preserve the mapped bytes. Resume with `SIGCONT` and one
more `I` byte. Successful exit requires exact session retirement, graceful
Gateway shutdown and socket removal. The owner must also terminate and reap the
entire owned process group on every error path.

## Exercised behavior

- The zero-grant Gateway rejects Topic, Service, Action, debug and update
  operations, and advertises no implicit publishers, subscriptions or services.
  Foreign `use_sim_time` parameter events cannot create a `/clock` reader.
- An unbound session, changed binding manifest, repeated binding, missing alias
  and different peer PID are refused.
- A real native Service receives the complete request and returns independently
  checked fields; a damaged canonical request causes no native service call.
- Topic data flows in both directions through actual DDS entities.
- A native client calls a Gateway-advertised Service; a correlated canonical
  response reaches the native future, and a repeated response is refused.
- A Gateway Action client receives actual feedback, success and cancellation.
  Another bound session cannot receive or cancel its goal; retired goal IDs do
  not become usable again.
- A native Action client calls a Gateway-advertised Action and receives actual
  feedback and a successful terminal result. Repeated terminal responses are
  refused.

The explicit `disabled-test` DDS security mode is confined to this isolated
fixture. It does not qualify production DDS credential enforcement. A successful
run applies only to the captured SDK, architecture, generated fixture and
Gateway executable. It is not evidence for every ROS distribution, vendor,
controller, firmware, QEMU target, hardware behavior, upstream official test
suite, or Native-versus-Wasm performance.

Production endpoint suppression uses
[the composed public SDK interfaces](../../../../../../src/ros/gateway/ros2/compat/README.node.md).
The fixture's Action status channel explicitly requests transient-local
durability, matching the original native Action client's status reader. A
volatile status writer cannot satisfy that durable reader; discovery delays
must not be hidden by silently changing the production capability's QoS.
