# Selected ROS platform SDK qualification

The Doosan lane uses `owner_doosan.py` and `pipeline_doosan.py` for twelve
separate original domains from all eleven observed public branches. AWS robot
and simulation workspaces remain independent. Nested service paths, complete
action components and the comment-only ROS2 disconnection DTO are retained.
That empty DTO is explicitly source-only until the native-topic profile can
admit it; no placeholder field or native identity is invented.

`discover_doosan.py` records inert branch/commit/tree JSON. The kit's capture
operator verifies each original Git blob, supports bounded stream-only codeload
archives and never materializes unrelated meshes or upstream executables.
Preparation can reuse exact completed source-generation receipts from a closed
failed earlier multi-domain preparation, after rechecking every original input
and generated byte. This reuses source data, never an execution pass. Every
subsequent compiler lane still independently builds each selected domain.

The direct, managed, CMake and cross harnesses use the profiles in the exact
pinned `profiles.json`. `inputs.json` records the completed direct vector
directory in `vectors` and actual attempt names in `qualification_attempts`.
`io_doosan_delivery.py` transports only the complete ordinary SDK/family source;
its local receive mode checks actual written bytes and executes no SDK tests.
`restore_doosan_inputs.py` admits explicitly selected frozen Runtime/QuickJS,
ordinary kernel UAPI and offline ROS XML data from closed r56 checkpoints.
Archived kernel symlinks remain metadata; actual per-target UAPI roots are used.

`native_doosan.py` builds selected unchanged Noetic and Humble original
interface packages in private network/mount namespaces with read-only native
SDK inputs. Select `native_profile`, use fresh attempts per profile and retain
the original CTest discovery/run outputs. `nativecheck_doosan.py` independently
checks source/tool/install-product hashes and registered test results. Zero
registered cases remain zero; these package builds do not replace full driver,
controller, simulator, target Runtime or VTune hardware-performance acceptance.

`prune_retained_doosan.py` admits only explicit closed `out/` objects that
still match a complete two-copy checkpoint and its independent client receipt.
It releases duplicate scratch data without touching source SDKs or shared
tools. `close_doosan_evidence.py` additionally requires the final independent
reports, a checkpoint covering every remaining tmpfs object, and no process
descriptor/cwd/root/mapping using that device before a normal unmount. Never
substitute a forced/lazy unmount or delete the retained evidence to clear space.

These operator harnesses distinguish original source coverage, real compiler
products, canonical data behavior, default refusal and native robot delivery.
The DOBOT lane covers the first four categories. The Flexiv lane also builds
selected unchanged original interface packages and executes their registered
package tests. Those package tests remain distinct from native robot delivery. No
source receipt, compiler success, QEMU exit or Wasm refusal is promoted to a
native ROS driver/controller, original official-suite or performance result.

Run all phases on SSH Linux inside the original hard64GiB, swap0 cgroup. A
caller must first create a fresh owned bounded tmpfs root, freeze ordinary
source/tool/Runtime inputs, and write `inputs.json` with:

- The exact boot ID, cgroup pathname/membership and device/inode identity.
- `source_root`, `runtime`, `validator`, the explicit installed `toolchains`
  directory and admitted original `quickjs` source root.
- Every selected ordinary input's absolute `path`, byte extent and SHA256 in
  `pins`. Source correspondence remains distinct from native metadata.
- For capture, one fresh `capture_output` plus either explicit original static
  `archives` (`ros1.tar.gz`/`ros2.tar.gz`) or previously captured
  `upstream_input`. No archive controller or upstream driver is executed.
- For cross data tests, `qualified_vectors` points to the actual completed
  qualification output containing its original-declaration reference vectors.

The cross lane also requires `kernel_headers`, an explicitly admitted private
root for the matching Debian Linux UAPI common dependency. `kernel_metadata`
and fresh `kernel_output` select the independently admitted signed metadata and
data-only extraction for the `kernel` phase. The required trusted signature and
package/index hashes are checked explicitly, including Debian's extra unknown
rollover signature. Target-specific asm roots precede generic kernel headers;
host libc/asm fallback and changes to a shared SDK are refused.

`run_dobot.py --root ROOT --phase PHASE --attempt NAME` owns capture, prepare,
assemble, qualify, managed, finish or cross. Use a fresh finite attempt name and
fresh inner output paths. Never overwrite an earlier failure or adopt a stale
`RUNNING` report as a completed pass. `assemble` emits examples/contracts only;
an operator must explicitly admit the resulting immutable source snapshot
before compiling it. Keep the exact source revision for each run.

All children run serially in owned process groups with finite wall/CPU/output,
descriptor and address-space bounds. Compiler phases have a sampled aggregate
RSS ceiling of 1.5GiB; source-only phases retain 768MiB. Actual Wasm products
have their own bounded linear memory. This is separate from the kernel's
aggregate hard64GiB limit, which is never raised. Admission credits only
conservatively measured inactive, ordinary, clean, unmapped, nonshared file
cache; tmpfs, dirty/mapped pages and other charges are not discounted. No
reclaim, `drop_caches`, sysctl or other task's processes are modified.

The C/C++ phase uses complete original records, transactional malformed/capacity
cases, and independently packed nonzero full-field vectors. Native and actual
Wasm executions are separate commands. The managed phase builds real Rust,
TinyGo, AssemblyScript and QuickJS/Wasm products, validates them, inspects their
actual imports and checks both state/query refusals. JavaScript's engine exit0
must additionally carry exact primary13/cleanup0 bytes; it is never sufficient
on its own. Complete managed record-value and positive native delivery testing
remain separate from this managed example lane.

The finish phase checks original commit/tree/blob/source/member/product
correspondence, exact profile selectors, actual CMake builds/executions,
wrong-domain and missing-selection refusals, default-OFF targets and byte-exact
example source reproduction. The cross phase compiles real x86_64, i686,
AArch64 and ARM hard-float ELF data programs and executes user QEMU. It does
not instantiate a target UWVM Runtime or infer a ROS distribution/sysroot,
big-endian/soft-float target, controller or ARM microarchitecture result.

Retain all actual argv, explicit environment, exit/status, input/output hashes,
products, original source, failed attempts, cgroup samples and cleanup receipts.
After full content/member/mode/EOF archive readbacks, normally unmount and remove
only the owned test root. Keep durable evidence under the fixed
`~/Documents/uwvm-test-261018/recovery/root` umbrella. Local source transport,
editing and inert readback do not count as local SDK/compiler/Runtime tests.

## Flexiv recovery and acceptance

`owner_flexiv.py --root ROOT --phase PHASE --attempt NAME` owns the selected
nine-profile source, data, language and native-package phases. Its additional
inputs are `vectors` (the completed `qualify` output), `qualification_attempts`
with `direct`, `managed`, `finish`, `cross`, and `native_attempts` mapping each
selected native profile to its fresh `build` attempt. A genuine later test
rerun may add `retest`; the independent checker then requires the preserved
original failure evidence. Never fabricate a rerun relationship after raw
evidence has been deleted.

The `schema` phase validates immutable official ROS XML commit/tree/blob data
and writes a private offline catalog. Admit its three output data files in
`pins`, then set `offline_ros_schema: true` for unchanged native package tests.
Original XML, test registration and private network isolation remain unchanged.
Noetic's original package registers zero cases; each selected Humble package
registers copyright, CMake lint and XML lint. These are package tests, not the
complete ROS, RDK, driver or controller suites.

For an explicitly admitted recovery volume, `recover` uses `recovery_volume`
and a fresh `sdk_recovery_output`. It copies only the selected Noetic, Humble
and cross SDK inputs, verifies every source/copy byte hash, mode, symlink and
hardlink group, and retains their inventories. The source volume must be
mounted read-only. `native_sdk_roots` may explicitly override each selected
native profile's root; `cross_sdk_root` and `aarch64_sdk_root` similarly select
actual target inputs. This restores input data without executing a cached
controller or changing the shared SDK. Cache recovery is not platform acceptance.

Retain a baseline before execution and each closed phase immediately:

```sh
python3 -I -S -B test/0073.ros-tests/support/source/ros_platform_sdk/retain_platform_evidence.py \
  --root /absolute/owned-tmpfs --label qualify-r1 \
  --destination /absolute/umbrella/recovery/ros-flexiv-r56 \
  --replica /absolute/separate-persistent-data/ros-flexiv-r56 \
  --include inputs.json --include control --include out/qualify-r1 \
  --include out/flexiv-qualify-r1.json --include out/commands/qualify-r1
```

Both archives receive full independent content/mode/member/gzip-EOF readbacks.
Regular objects are deduplicated by content and mode. Symlinks are inert
manifest metadata; no link or executable is extracted. Source/tool pins and
original role paths remain in each owner report. Replicate outside Documents
and outside a disposable SDK image; a second filename on the same deleted
test tree is not independent retention. `read_platform_evidence.py` accepts a
streamed archive on stdin plus its expected compressed size/SHA256, checking
every object without saving a large local archive or running local tests.

After the r55 test tree was deleted, its observed results were explicitly
marked as lacking raw evidence. The r56 recovery uses fresh attempts and
independent readbacks rather than adopting those old success counts. Consult
the [Flexiv delivery record](../../../../../documents/ros/flexiv-complete-source-sdk-20261020.md)
for the actual closed recovery results and remaining acceptance scope.

## RealMan complete branch source and native package lanes

`owner_realman.py` and `pipeline_realman.py` keep the five original ROS1
develop/main and ROS2 Foxy/Humble/Jazzy domains separate. Source capture supports
bounded immutable archives, complete Git blob checks and explicit partial
ordinary-source caches; it never executes an upstream installer. Core sources
are explicitly admitted from the retained complete original core capture.
Source preparation admits the exporter and all four RPC templates before any
profile output. Incomplete transport failures remain operator failures.

`batch_realman.py` retains a joined direct qualification, then runs managed,
CMake and four-architecture data phases serially. `verify_realman.py` checks
actual products, bytes, memory, refusal outcomes, ELF identities and the exact
current source-delivery set. `audit_realman.py` checks the current 65-family
source census and its expected all-vendor CI refusal.

`native_realman.py` builds selected unchanged interface packages in the admitted
Noetic/Humble read-only SDK namespaces. The original Humble CMake lint failure
is retained. `batch_native_realman.py --format-only-rebuild` explicitly creates
the reviewed private two-space overlay, rebuilds and reruns all registered cases.
`nativecheck_realman.py` separately verifies original failure, downstream cases
and every compared native header/declaration. It never changes upstream bytes
or labels the downstream result an unmodified original-suite pass. Noetic has
zero registered interface-package cases; none is invented.

See the [RealMan delivery record](../../../../../documents/ros/realman-complete-source-sdk-20261020.md)
for precise executed scope. Native interface-package construction remains
distinct from positive robot traffic, whole driver suites and hardware performance.
