# Direct Go2 six-Guest build configuration maker

`../make_direct_build_configuration.py` is an external SHA-bound metadata entry.
It does not compile or start a child. It emits an ordinary Unitree Frame config,
closed Direct-build selection and unexecuted invocation for the frozen
`prepare_direct_guests.py`. The actual six-product build is a separate Root-owned
phase and requires its own compile/link/validator/cleanup receipt.

## Closed actual request

Fill `request.template.json` using current stable ordinary file observations.
Every file selection is exactly `{path, bytes, sha256, device, inode, mtime_ns,
ctime_ns}`. Nulls deliberately fail. The request itself and the executing maker
must be selected through their actual SHA256 arguments.

The ten selected tools/archives are `cc`, `cxx`, `python`, `validator`, `libc`,
`libm`, `printscan`, `builtins`, `libcxx` and `libcxxabi`. `python` must be the
actual executing Python. All other request pins are likewise current complete
observations, not old-device pins supplied as current. The four SDK paths are
`sysroot`, `resource_dir`, `wasm_ld_alias` and `quickjs`. Directories must be
physical complete inputs. The final Wasm-linker filename may be the actual
multicall symlink spelling beginning `wasm-ld`; its parent must be canonical,
its complete target is fully hashed, and its literal link observation and target
are checked again before metadata acceptance.

The two C++ archive inputs must be an explicit same-profile physical pair in
`sysroot/lib/wasm32-wasip1`, or its `noeh` or `eh` subdirectory. SDK33's selected
`noeh` pair does not use the historical flat spelling. The current maker and
real Direct producer use the same complete-MF-loaded Legacy layout policy and
retain the actual selected full-seven inputs; neither searches for a fallback.
C archives keep their exact flat WASIp1 paths. See
[`DIRECT_WASI_CPP_ARCHIVES.md`](../../DIRECT_WASI_CPP_ARCHIVES.md) for current
Typed14 and independent A1/A2 routes and their distinct metadata/link claims.
The sealed Source43 `derive_request_r2.py` and `make_metadata_launch_plan.py`
remain historical controls, including their old flat lookup; do not use them
to derive a current SDK33 request. Fill the current request's explicit
`libcxx`/`libcxxabi` full-seven pins instead.

A native retained74 receipt, interpreter Worker binary, mapped SDK role set,
network namespace or simulator view is not a Direct-build prerequisite. This
maker does not query interfaces or require a loopback namespace. The shared
entry is loaded only for its reviewed file/root planning utilities; its Typed28
bootstrap/admission/main are not called. Raw cgroup identity/membership/hard
limits are checked before loading that helper; selected frozen common/probe
then provide the complete live ancestor/OOM/memory guards.

## Derivation and real prerequisite validation

The maker reads the original completed Typed14 report without editing it. It
selects its actual official termination object qualification and original
complete GO24 family, retaining original source labels. It reopens selected
full-MD/qualification references through explicit device-only mappings. All
same-device changes and every path/inode/time/byte/SHA mismatch are refused.
Multiple old devices for one current root require separate unique
`(root, historical_device)` mapping rows; no map grants an extra input path.

Complete root candidates come only from the actual producer's inventories,
its exact output directory, original complete source/manifest directory and
fresh controls. No broad guessed parent is introduced to fit the64-root limit.
Selected SDK/QuickJS/GO paths keep complete root coverage even when a sparse
metadata pin list has not touched a file there yet. Controls are sealed before
Frame input inventory begins.

The maker calls only the selected frozen preparer's `prerequisite()`. That
independently verifies the actual original official C++ object/producer,
termination policy, complete GO24 generation/output definitions, native catalog,
current profile/emitter bytes and historical source relation. The maker also
matches the selected actual C++ compiler/sysroot and archive paths against that
qualification. It never invokes `build()` or creates a compiler owner.

Terminal checks rehash all current bootstrap/tool/planning inputs, complete
source, linker target/alias and Frame inventories. The future build output must
remain absent and the actor list empty. Live maker RSS is bounded1536MiB,
cgroup headroom is at least4GiB, and the8GiB backing reserve is checked through
its active guard. A failed reserve or missing receipt stops preparation; no
partial successful compiler result is invented.
