# Fortran 与 WAT 库验收

这两条路线等待唯一公共 Flang23 适配器、真实目标运行库，以及固定源码身份的
WAT 汇编链接器。平台提供原始完整类型目录，不私藏编译器，不用 C 替代 Fortran。
每组件须有三个不同编解码例子，分别证明真实32/64位。NVIDIA总入口明确选择组件，
复用其公共模块。

binary 为一个应用Wasm；shared 为独立装载且记录导入、导出、自有内存的Wasm；
static 内含真实可重定位对象。使用普通Xmake kind和依赖选项。文本汇编通过不等于
归档、原生通信或动态模块互操作通过。

静态库须保存源码哈希、真实编译器/汇编器版本及命令、对象元数据、带索引归档、
链接器符号提取记录和最终消费者Wasm。未引用的哨兵成员必须未提取，并实际运行
消费者。wasm_archive.py只作有界成员准入，不代表编译、链接、提取或执行验收；
把不含linking元数据的完整最终模块塞进归档会被拒绝。

共享图明确命名io、algorithm、ros_comm，模块间使用标量或模块自有token，保留
全位宽句柄和明确退休。真实Fortran bind(C)签名须与WAT实际导入一致。
algorithm只保留默认WASI且没有额外ROS授权；只有ros_comm获得手工配置的原始
Array精确别名。不得修改提交的权限配置。

正向通信、未授权调用、关闭撤销、传递依赖、导出冲突、位宽及签名错误均须在x86
和QEMU ARM执行。独立观察每个原始字段，包括两条检测和72个协方差值。
沿用现有源码配对的VM、网关和原生夹具。物理GPU/NITROS、ARM编译宿主独立开放。
每作业持全局锁，记录自己的64GiB、零swap实测门禁。
