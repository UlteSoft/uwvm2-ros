# Native architecture acceptance

`test/0073.ros-tests/sdk/tools/aarch64/run_container.py` is the Linux host entry. Transfer the entire owned work folder first. Supply `--work`, an installed `--image`, a fresh `--label`, and the common `--lock`. Each dependency uses an explicit `--read-only HOST:/deps/NAME`. A command after `--` runs inside the container. The runner holds flock until that unique container exits and is removed. Actual kernel cgroup files must show `memory.max=68719476736` and `memory.swap.max=0`; requested Docker options alone never qualify a batch. The default network is isolated; optional bridge networking is only for verified source acquisition. Existing containers and unrelated processes are untouched.

`accept.py --manifest INPUT --output FRESH_DIRECTORY` runs inside that batch. Input format is `uwvm-native-acceptance-v1`. Declare `target_machine=183` for genuine AArch64 processes under explicit QEMU or 62 for a separately recorded x86_64 cohort. Every asset supplies a complete path, exact SHA-256 and role. Runtime, gateway, native peer/interpreter roles require actual ELF64 bytes matching the target machine. QEMU has its own independent ELF identity and version. Scripts can be launcher assets only when they explicitly name their paired runtime asset; a script hash never replaces the runtime ELF hash.

Peers have unique IDs, exact argv, optional explicit environment and bounded readiness. Readiness is either a complete JSONL native event subset or text in an owned log. Assets expand as `${asset:NAME}` and the fresh result directory as `${output}`; unknown placeholders are refused. The runner starts a separate owned process group, captures complete stdout/stderr and live loader maps, and records persistent mapped ELF identities. It stops/reaps only those groups. Forced cleanup remains visible and fails the cleanup acceptance row.

Cases name the exact admitted Wasm, SHA, memory bits, argv, expected exit code and native witness. The admitted runtime or its paired launcher and exact Wasm must occur in argv. Defined memory flags are inspected; imported memories, truncated metadata and mismatched pointer widths fail admission. The real runtime still performs authoritative Wasm validation and execution. `stdout_contains` checks complete observations. A witness selects complete native JSONL fields; `wire_stdout_regex` additionally compares its captured full hexadecimal body to the peer's `wire_hex`. Publication/service/action witnesses normally must arrive after the case starts. A subscription may explicitly use a readiness witness if its guest output independently proves the full received value.

For a multi-module case, add `main_module_name` and an ordered `preload_modules` list. Each entry has `name`, `wasm`, `sha256` and `memory_bits`. The exact manual argv must include `--wasm-set-main-module-name main` and, in declared order, `--wasm-preload-library /absolute/module.wasm module_name`, followed by the main `--run` command. The rename is one plain argument; parentheses in the CLI usage denote an optional argument and are not literal name characters. The runner records each module's actual bytes and memory flags, requires every preload to be declared, and adds no preload, grant or policy itself.

A pure function library with no memory declares `memory_bits: null`; this does not prove a pointer width. Imported memory remains unqualified. Declared widths must match actual module bytes; intentionally different module widths and duplicate names can be retained for real VM refusal tests. Use the exact nonzero `expected_exit_code` with `stderr_contains` for the native loader diagnostic, plus a native absent-effect witness. Metadata admission does not prove export/import binding, collisions, archive extraction, cross-module memory safety or ROS Single isolation. Those require actual producer/consumer and native peer execution.

Denied permissions use `native_witness.absent` and a bounded 0.1–5 second quiet window. Native events matching that effect must remain absent. Initial and per-case `fixture_files` can set explicit peer-mode data only below the fresh output directory. They do not edit a runtime policy. Each production launcher must retain its own full runtime/gateway receipt, primary status, actual lengths and independent resource cleanup; preserve those original logs alongside the harness receipt. A peer-generated success flag or a guest exit code alone is not acceptance.

A source-built native binary is not proof of an ARM compiler host. The receipt always records `arm_compiler_host_qualified=false`; an actual ARM-native Xmake/frontend source build needs a separate measured batch and row. QEMU user mode does not qualify physical ARM hardware or an ARM kernel. ROS fixture messages/services/actions do not qualify GPU training, inference, simulation, sensors or robot actuation. Each group provides its own original typed native peers and full codec/service/action cases through this common runner.

`acceptance.json` is written before each next effect and retains failures. `files.sha256.json` seals every retained raw result except itself. Reusing a result directory is refused. The metadata inspector's unit tests live in `test/0073.ros-tests/sdk/tests/aarch64`; synthetic metadata fixtures test refusal boundaries and are never executed as runtimes.

Use --tmpfs-mib to select512..8192MiB of executable scratch within the same unchanged64GiB cgroup. The default is512MiB. This budget is charged to that cgroup; it grants no host mount or extra RAM. Explicit dependency mounts stay read-only.
