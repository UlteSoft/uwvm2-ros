# AgileX SCOUT ROS2: complete selected generated values

This actual six-language generation retains 15 complete records and ten
original constants for the pinned original SCOUT catalog and its full standard
dependency closure. No native registry or permission is emitted. The original
producer receipt is `generation.vendor.json`; source preparation is recorded
separately in `preparation.vendor.json`. Neither receipt is a native driver,
compiler, Wasm execution or physical robot certificate.

Read the [complete model and build guide](../../robots/mobile_bases/agilex/scout/README.md)
for raw imports, C/C++ checked operations, six-language examples, exact endpoint
and protocol differences, bounds, default-zero authority and remaining work.
Keep this whole directory exactly one level below `sdk/custom-types` so the
genuine AssemblyScript relative imports resolve. Never combine its record
headers with a different ROS major or another separately generated catalog.

C includes `bounded_records.h`; C++ uses `bounded_records.hpp` and the matching
`roswasmcpp::Codec<T>`. Rust requires the actual core crate with `alloc` and the
selected backend feature. JavaScript uses complete immutable Codec values and
a genuine copied Guest Session. AssemblyScript uses `encodeChecked` and
`decodeChecked`; inspect status before accessing a value. TinyGo keeps generated
records in a separate package and selects the actual Wasm/backend build tags.

All original fields remain, including counted Header text, fixed actuator or
motor/driver arrays and both full odometry covariances. Native field presence
does not establish real sensor validity: the pinned ROS1 BMS assignments are
commented out, and some protocol/model fields are not populated by that driver.
Use independent original Native observations before treating a value as fresh.
