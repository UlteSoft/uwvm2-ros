# Complete official standard records

The additive `uwvm-ros-official-standard-bounded-v1` source profile supports
complete ROS1/ROS2 Header and JointState declarations, plus ROS1 primitive time
and duration and ROS2 builtin Time/Duration dependencies. Its additive
[geometry/navigation family](official-geometry-nav/README.md) supplies complete
admitted geometry, covariance, transform, odometry and path records. It keeps the original
fixed-v1 and custom bounded-v2 profiles unchanged. It is an explicit opt-in
source format, not an implicit permission or an arbitrary IDL implementation.

Start with the [raw import reference](../docs/abi-v1.md), then the ordinary
[SDK language lessons](../README.md). The concrete
[JointState applications in all six languages](../robots/vendors/examples/joint_state/README.md)
show a complete typed subscription and checked ownership cleanup. Their
comments cover actual imports, complete generated values, caller-driven polling,
errors, default denial and explicit positive mode selection.

## Prepare original declarations and actual native identities

1. Select one exact robot model, SDK revision, ROS major and official interface
   source revision. Preserve the complete original definitions and their license;
   do not infer a controller/firmware version from a vendor name. Use the
   [vendor source preparation pipeline](../robots/vendors/README.md) to admit
   that source and all transitive dependencies.
2. Set the catalog format to `uwvm-ros-official-standard-bounded-v1`. ROS1 names
   are `std_msgs/Header` and `sensor_msgs/JointState`. ROS2 names are
   `std_msgs/msg/Header`, `builtin_interfaces/msg/Time` and
   `sensor_msgs/msg/JointState`. Keep official fields and declaration order.
   Header/Time/Duration are dependency entries with `registered: false`;
   JointState and admitted geometry/navigation Topic entries use their explicit
   registration markers. Unknown standard names
   and existing builtin String/Bool/Twist/Image replacements are refused.
3. Supply explicit finite canonical limits for every dynamic field, including
   frame_id, each name string and all four sequences. These limits may be
   stricter than an unbounded native declaration; they never replace the actual
   native string/sequence capacity in native identity or schema comparison.
   Every complete canonical record remains subject to the profile's 32768-byte
   limit. Oversized messages are refused rather than truncated.
4. Compile and execute the actual native identity exporter against that installed
   SDK under its external process owner. Preserve original compiler/frontend,
   complete dependencies, linked libraries, stopped-process mappings, raw output
   and terminal cleanup evidence. Bind only those actual native identities.
   Guest-only generation does not authorize a native endpoint. ROS1 primitive
   time/duration has no fabricated Message MD5; its real C++ field types are
   checked independently.
5. Generate the complete six-language/native bundle from the bound catalog,
   retain its generation receipt and all source inputs, then stage the entire
   actual bundle as `sdk/custom-types/generated-official-standard` in a fresh
   SDK layout. Verify every output extent/hash. Do not write a placeholder
   header, native identity, codec identity or hand-computed maximum to make an
   example compile. The emitted AssemblyScript relative SDK import must remain
   valid, and the TinyGo package copy must preserve generated bytes.

The implementation's unbound declaration fixtures and native contracts are in
`tests/ros_custom_types/official-standard` in the full source repository. Those
transparent fixtures are not a receipt for acquiring an immutable SDK. Exact
model preparation must retain the independently acquired original sources.

## Complete values and public language APIs

| Language | ROS1 generated record | ROS2 generated record | Complete decoder/bound |
| --- | --- | --- | --- |
| C | `roswasmc_bounded_1_sensor_msgs_JointState` | `roswasmc_bounded_2_sensor_msgs_msg_JointState` | Record-prefixed `_decode` and uppercase `_MAX_WIRE_BYTES` |
| C++ | `uwvm_custom::Ros1Sensor_msgsJointState` | `uwvm_custom::Ros2Sensor_msgsMsgJointState` | Actual `roswasmcpp::Codec<T>` specialization and `max_wire_bytes` |
| Rust | `Ros1Sensor_msgsJointState` | `Ros2Sensor_msgsMsgJointState` | Actual `Canonical` implementation and `MAX_WIRE_BYTES` |
| JavaScript | `Ros1Sensor_msgsJointStateCodec` | `Ros2Sensor_msgsMsgJointStateCodec` | Complete `decode` and `maxWireBytes`; use the real JS-in-Wasm Guest transport |
| AssemblyScript | `Ros1Sensor_msgsJointState` | `Ros2Sensor_msgsMsgJointState` | Corresponding `Codec`, `valid` before `decode`, and `maxWireBytes` |
| TinyGo | `Ros1Sensor_msgsJointState` | `Ros2Sensor_msgsMsgJointState` | `Decode<Record>` and `<Record>MaxWireBytes` |

Every record contains header, name, position, velocity and effort. ROS1 Header
preserves seq and unsigned sec/nsec. ROS2 Header has signed sec and unsigned
nanosec and has no seq. Nanoseconds must be normalized to [0, 1000000000).
Every nonempty JointState array has the same length; optional empty arrays
remain empty, including an all-empty value. Decode validates the entire input
before exposing a typed value. Trailing bytes, malformed Unicode, out-of-range
counts and invalid full values fail without a partial destination commit.

The concrete examples compare every field, including an empty velocity array
and a negative ROS2 second. Default mode requires actual open error13 with no
handle; a successful open, idle11 or unsupported95 cannot pass that case. A
separately compiled positive mode needs one explicit `joint-state` subscription
alias. Basic stdin releases at most64 poll credits; no Guest timer, clock,
network, thread, environment or management right is added automatically.

The generated native registry describes implemented types and grants nothing.
Only trusted Host policy can enable the backend and provide a model-specific
resource, native identity, codec identity, QoS and finite budgets. Guest code
cannot register arbitrary schemas or call update/debug/policy controls.

## Qualification still required

Source and examples are integrated and independently reviewed. This new profile,
its source-policy/native contracts and the 24 six-language/backend/mode recipe
entries have not yet been generated, compiled or executed in the unified lane.
A full-value marker is not proof of ROS publication, a completed vendor adapter
or official-suite coverage; actual independent native publication and complete
process/SDK/source evidence remain required.

The exact official ROS2 Quaternion declaration initializes x/y/z to0 and w to1.
All six generated language constructors/initializers retain that default,
including nested records. The modern native TypeDescription must independently
match its canonical default text. RIHS omits defaults and cannot alone establish
this fact. An old introspection pointer cannot prove the same default contract;
the explicit legacy route refuses declared defaults. This source implementation
still requires real generation, constructor and native-metadata qualification.

The [required implementation gap ledger](../../tests/ros_custom_types/official-standard/required-implementation-gaps.json)
keeps the remaining standard types, sensor nonfinite values, arbitrary constants/defaults,
wide strings, large-image capacities, IDL and version/native coverage explicit.
These are required follow-up implementations. The admitted standard families do
not claim to close every vendor's custom interface or native rclcpp API.
