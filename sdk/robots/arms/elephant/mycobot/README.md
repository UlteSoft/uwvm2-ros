This kit retains every original message/service/action declaration in six pinned
official mycobot_ros / mycobot_ros2 Git trees. The original interface bodies,
comments, exact package XML/CMake, available root README/license and whole Git
tree/commit evidence are retained unchanged. The generated bounded C, C++, Rust,
JavaScript, AssemblyScript and TinyGo products preserve every original field and
component. They are source migration inputs through Wasm and controlled ROS
imports; they are not native rcl binary objects or a native Python robot SDK.

## Start at the actual raw import boundary

Read sdk/include/roswasm/abi/ros1.h or abi/ros2.h and the matching C backend.
The C/C++ entry accepts exactly raw ALIAS or state ALIAS. The alias is an
explicit nonempty operator input. raw opens/closes once; state additionally
subscribes/polls once and writes a complete canonical observation to basic stdout.

Default ROS authority is empty. Importing, constructing, compiling or selecting
a vendor/model does not acquire authority. An ungranted alias must refuse13.
The operator must independently bind module/backend, alias/endpoint, direction,
operations, original native/canonical identity, QoS and finite resource budgets.
No example discovers a port or credentials, opens native serial/CAN/socket
resources, installs pymycobot, starts a ROS service, enables a host debugger or
updater, changes environment/policy, retries motion or resumes a robot.

The host native Gateway/robot bridge is a separately configured trusted process.
An SDK source hash is not a signature, native MD5/TypeDescription or permission.
Native firmware/driver requirements and physical safety supervision remain
independent. Resource close is cleanup rather than an emergency stop.

## Progress to complete typed records and services

include/state.h borrows a real explicitly owned capability and caller scratch.
uwvm_elephant_poll_state decodes the whole selected state transactionally.
Keep scratch and destination disjoint and serialize access to the capability.
Idle11 never replaces an observation; error90 never grows buffers or replays.
C++ include/state.hpp adds a borrowed Reader and includes the original generated
typed service/action facades. Only interfaces actually present in the source
domain acquire a generated facade.

uwvm_elephant_make_observation is a pure complete-value constructor. Supply
exactly UWVM_ELEPHANT_COMPONENTS values plus explicit finite min/max arrays in
the selected original declaration order and original driver units. It performs
no degree/radian or model conversion. It checks all values before commit and
checks float32 bounds again after rounding. Refusal preserves the destination.
This constructs observation data, not a command, permission, publication, stop,
acknowledgement or recovery operation.

Use bounded_records.h/.hpp for complete command values and
bounded_interfaces.h/.hpp for all original request/response components and
explicit owned service operations. The six generated record modules expose
every original field. Rust/Go copy complete record and interface modules.
JS uses an actual copied Session; AS uses the actual selected NativeApi.
Primary, cleanup, decoded value and terminal result remain distinct.

Strings, when present, have a finite 256-byte UTF-8 bound; variable sequences
have 32 elements or the smaller original declared limit. Fixed original array
extents remain exact. These are explicit bounded canonical SDK profiles, not
changes to the original unbounded ROS types. Excess is refused without
truncation. Review and regenerate another finite profile if an application
needs a different capacity. No quota adjustment implicitly grants a capability.

## Build genuine C/C++ examples

Choose APP from the thirty explicit names and its corresponding DOMAIN.
All CMake targets default OFF; missing or mismatched model/domain inputs refuse.

```sh
cmake -S "$KIT" -B /tmp/elephant-example \
  -DUWVM_ELEPHANT_BUILD_CONTRACTS=ON \
  -DUWVM_ELEPHANT_SELECTION="$APP" \
  -DUWVM_ELEPHANT_SOURCE_ROOT="$SRC" \
  -DUWVM_ELEPHANT_GENERATED="$SRC/sdk/custom-types/elephant-mycobot-$DOMAIN-complete"
cmake --build /tmp/elephant-example --parallel 1
```

For genuine WASI entries add the actual WASI toolchain and
-DUWVM_ELEPHANT_BUILD_WASI_EXAMPLES=ON. Constrain the initial compiler-identify
link as well as target links, for example
-DCMAKE_EXE_LINKER_FLAGS=-Wl,--threads=1. Run elephant_guest_c.wasm or
elephant_guest_cpp.wasm with raw ALIAS or state ALIAS through uwvm2.
An ungranted alias is expected to refuse13.

Runtime --ros-vendor-elephant defaults OFF independently of --import-ros1/2.
Native selection requires a separately genuinely bound coherent manifest.
The A+B configuration printer can select Elephant with another vendor and
explicitly disable all other options. Adding SDK source does not link every
robot SDK into the Runtime. Combining vendors requires one coherent compatible

## Build genuine Rust, AssemblyScript, TinyGo and JavaScript entries

Rust: from examples/rust, use
cargo build --offline --release --target wasm32-wasip1 --no-default-features
--features APP -j 1. Exactly one model/domain feature is required. The full
matching record/service modules compile. Run elephant-state.wasm ALIAS.

AS: compile examples/main_APP.ts with the actual AssemblyScript compiler,
incremental runtime, explicit memory bounds and
--use abort=sdk/assemblyscript/api/abortGuest. Basic stdin contains one nonzero
u8 byte count followed by that many strict UTF-8 alias bytes. lastValue changes
only after a complete checked decode; cleanupStatus stays separate.

and elephant_APP selection, for example
tinygo build -target=wasi -tags=ros1,elephant_kinetic_mycobot
-scheduler=none -gc=leaking -panic=trap -p=1 -o /tmp/elephant.wasm .
Run with one explicit alias. Missing, duplicate and backend-mismatched selections
must refuse compilation. Complete copied records/interfaces are checked against
the corresponding canonical generated source bundles.

JS: examples/javascript-APP.json is a closed genuine QuickJS-in-Wasm recipe.
Use sdk/javascript/guest/prepare.py with actual original QuickJS sources,
the WASI compiler/libc/builtins and full validator, then execute its exact

separate from ROS success. Host Node/ROS modules are not substitutes.

## Reproduce independent whole-field validation

tests/validate_sources.py --source "$SRC" verifies every original custom root,
commit/tree/blob, component field, generated product, public symbol in all six
languages and exact domain association. Authored C/C++ contracts cover every
complete record, every truncation point, trailing-data refusal, undersized
output preservation and complete model-specific observation construction.

The independent golden generator does not import the codec generator or its
field IR. It parses unchanged original declarations, selects deterministic
nonzero values and packs separate canonical bytes using Python struct.
Managed tests assert every named decoded field before re-encoding, preventing
an inverse encoder/decoder field swap from hiding behind a round trip.
Synthetic values are test data, never commands sent to a robot.

```sh
for DOMAIN in kinetic melodic noetic foxy galactic humble; do
  python3 -I -S -B "$KIT/tests/generate_golden_vectors.py" \
    --source "$SRC" --profile "$DOMAIN" \
    --out "$WORK/golden-vectors-$DOMAIN"
done
python3 -I -S -B "$KIT/tests/generate_managed_golden.py" \
  --source "$SRC" --vectors-root "$WORK" --out "$WORK/managed"
python3 -I -S -B "$KIT/tests/split_managed_golden.py" \
  --inputs "$WORK/managed" --out "$WORK/batches"
```

Compile each bounded batch with real assertions enabled and execute actual
native/Wasm/QEMU artifacts. For AS batches use the explicit common
--baseDir "$WORK" and --use abort=source/sdk/assemblyscript/api/abortGuest.
Preserve relocated SDK imports. JS batches must execute inside actual QuickJS
Wasm, not a host Node substitute. Use one compiler job and retain cgroup,
virtual-address, linker-thread and explicit memory guards.

These authored source/data/default-denial contracts are not the original
official suite. Preserve actual Guest results, positive native observations,
driver/model/firmware/controller acceptance, simulator, requested x86/Arm Runtime
tests and equivalent-work VTune hardware-counter measurements separately.
No complete-vendor, all-release, official-suite or hardware-performance claim
is inferred from this source guide.
