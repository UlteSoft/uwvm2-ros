# Python ROS Wasm SDK

This SDK runs real Python inside a statically linked CPython/WASI interpreter.
`_roswasm_native` is a built-in C extension calling the actual ROS Wasm imports.
It does not use host Python, a network relay, `ctypes`, a native rclpy wheel or
JavaScript host callbacks. Importing the SDK opens no ROS resources.

The current producer is CPython 3.14.8 with WASI SDK24. Its generic language
producer belongs to `test/0050.high_level_languages/python`; the ROS extension,
application ownership and migration code belong here. Generic interpreter
tests are distinct from ROS SDK qualification.

For language-frame debugging, follow the [CPython debug build guide](debug/BUILD.md).
It provides the actual non-ROS probe, five build steps, artifact checks and ROS
embedding instructions. The current complete toolchain dependency capture and
usable debugger qualification are still pending.

## Start with exact imports

Compile `roswasm/_native.c` with `-DROSWASM_BACKEND=1` or `2`, target CPython's
`pyconfig.h`, its `Include` directory and the SDK root include path. Each build
imports only the selected backend. ROS1 has38 functions; ROS2 has43. Their
memory index is i32; offsets, lengths, handles and correlations are i64, including
on wasm32. Output slots are eight-byte little endian values.

The generated C dispatcher is reproducible with:

```sh
python3 -B sdk/tools/generate_managed_raw.py --out /tmp/managed-raw-review
```

Review the generated bytes against [the ABI schema](../abi/abi-v1.json).
`Backend.invoke` supports every selected function through a copied-buffer
interface. The C bridge pins the input buffer until the synchronous import
returns and owns its output bytes. No Python object address is exposed.

| Form | `invoke` arguments beyond the operation name | Outcome |
| --- | --- | --- |
| version | none | `value` is the ABI version |
| open | `payload=alias.encode('utf-8')` | successful `value` is a nonzero handle |
| handle | `handle=owner` | original errno |
| write | `handle`, complete canonical `payload` | original errno |
| poll | `handle`, explicit `capacity` | owned `data`, or conditional `required` |
| watch | observer `handle`, source `other`, `correlation` | original errno |
| ready | observer `handle`, `capacity=32` | four exact u64 counters |
| submit | source `handle`, observer `other`, request `payload` | admitted request ID in `value` |
| rpc | `handle`, request `payload`, response `capacity` | owned complete response or original failure |

`Result.error` is separate from data/size/value. Error90 does not necessarily
write a length. An unwritten length stays `None`; a timeout110 can follow an
admitted effect. The library never automatically retries a call, resizes and
replays a consumed receive, substitutes another backend or broadens authority.

## Own resources explicitly

```python
from roswasm import Backend, Session, Node, codecs

with Session(Backend(2)) as session:
    publisher = Node(session).create_publisher(codecs.String, 'publish')
    publisher.publish('robot status').checked()
```

`publish` must already be an explicitly granted alias in the trusted Host policy.
Its actual native resource/type/QoS/quotas are not selected by the message text.
The context manager checks ABI1 and closes every live owner in reverse order.
Cleanup failures remain separate from application exceptions. An owner is
locally retired before its close import; a failed close is not replayed.

The [annotated examples](../examples/python) progress through actual default
denial, typed topics, Trigger and Fibonacci. Positive examples require actual
native peers and independent observation; publishing and receiving through a
local test double does not qualify them. Stdin credits bound polling without
an implicit clock or background thread.

`ServiceServer` keeps advertise/respond owners distinct and preserves the exact
request ID. `ActionClient` tracks its outgoing goal IDs and requires separate
send/feedback/result/cancel grants; cancel-any remains an independent raw
operation. `Observer` validates full64-byte envelopes and one monotonically
increasing sequence across its interleaved sources. `Executor` uses bounded
round-robin passes on the guest thread. Parameter/TF/graph/lifecycle/time/log
families remain available through `Node.open_operation(alias).invoke(...)` with
their exact canonical codecs; no empty request means unrestricted discovery.

## Build an executable interpreter

Use the matching native build-Python to run [tools/freeze.py](tools/freeze.py).
It preserves package names and freezes the selected entry, SDK and pure Python
stdlib into `roswasm_frozen.h`, recording original source and bytecode hashes. The
compatibility closure selects the explicit `rclpy`, `std_msgs`,
`example_interfaces`, `std_srvs` and `examples_rclpy_minimal_service` package
roots, preserving their import names. Preserved upstream audits, build scripts
and standalone examples are not implicitly frozen as application modules. The
application entry is chosen only with `--entry` as `roswasm_app`; freezing a
package does not execute its code or grant it any Host authority.
Build [embedding/main.c](embedding/main.c) with that header, the selected bridge
object and the **actual target** `libpython.a` and generated link libraries.
The launcher registers `PyInit__roswasm_native` before interpreter startup.
Entry `main()` may return `None` or an integer0..255.

Do not use the host interpreter to create target bytecode. Do not assume a
frozen pure Python module supplies unavailable WASI C extensions, pthreads,
processes, sockets, `asyncio` transports or dynamically loaded ROS type support.
The native/WASI module closure must be exercised with the exact producer.
The current launcher requests no directory/environment/clock/random grant.
Any genuinely required permission must be explicit in the Host CLI and reported
separately from ROS default denial; never widen Runtime defaults to make a
language startup test pass.

## Migrate existing rclpy source

The opt-in `compat/rclpy` root preserves familiar `rclpy`, `rclpy.node`, QoS and
`std_msgs.msg` imports for the currently implemented profile. A deployment
bootstrap configures exact operation/resource/type/QoS-to-alias bindings on the
Context before `rclpy.init`. This is local symbol selection, not Host policy
management. Missing bindings fail with13; mismatched QoS fails with17 before
an endpoint opens.

Full rclpy compatibility is a required ongoing task. The additive service
profile supplies typed AddTwoInts/Trigger/SetBool request and response codecs,
real asynchronous submit/observer integration, exact request IDs and the bounded
Future subset documented in the compatibility ledger. Its local contract checks
do not establish native ROS delivery. Parameter services, generated message
introspection, native identity, callback groups, complete Future/Task and Action
APIs, remapping, jump callbacks, actual service availability and native wait-set
blocking still require implementation and upstream tests.
Nonblocking `spin_once(..., timeout_sec=0)` is explicit. Blocking `spin` currently
requires a deployment idle driver and is not presented as native wait-set
equivalence. See [the compatibility ledger](../compatibility/rcl/README.md).

## Verify without confusing test levels

Copy this directory and any examples under `/tmp` before local tests. With that
copy as the current directory:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=.:compat/rclpy:tests \
  python3 -B -m unittest discover -s tests -v
```

These are local wire/lifetime/migration-profile tests. Separately inspect the
linked module with `sdk/tools/check_wasm_imports.py --backend 1|2 --require-all
--allow-module wasi_snapshot_preview1`, validate the whole Wasm, then execute
default-denied and granted cases in the real Runtime/Gateway/native ROS matrix.
All task Linux tests stay in the existing64GiB zero-swap cgroup. No guest import
can update Wasm, configure the debugger or change Host grants.

return the exact expected denial marker. Native bridge objects, actual target
Makefile library order, frozen source/bytecode, final imports and unchanged

not claim two independently optimized interpreter builds. Positive subscription
modules are built but have no native JointState delivery credit. Native DWARF
is retained; Python frame-snapshot debugging and VTune performance qualification
are separate tests. The record also discloses a scratch-path resource-accounting
limitation in the original candidate monitor, with final actual-tree inventory.
