## One retained actual client or service

Activation reserves one permanent source slot before ABI discovery/Native call.
Failed attempts are not silently reused. A successful exact UMRE256 must contain
client3 or service4, actual two QoS profiles, complete full64 source/instance/
generation/session/native incarnation and strict reserved/tail bytes. All eight
QoS domains are decoded; normalized wire durations remain distinct from original
RMW argument representation. B's linked genuine `rmw_time_equal` compares actual
effective QoS against its independently selected row. No requested/default QoS
is called an observed native result.

A service has no native client GID. A client may have an actual0..32-byte GID,
which is preserved completely in the endpoint receipt. Zero bytes are real data;
an absent GID is explicit extent0. That global client GID is not the native
request writer GUID and is not a local RMW request ID. Width-incompatible global
GID remains preserved in the actual receipt and cannot be truncated/invented to
make a public getter pass. Existing C exposes a public client GID only when the
complete actual width matches its original selected SDK.

Inspection reuses the same retained object and compares its complete original
wire except the command byte plus all actual profile/binding fields. The actual
Native helper's canonical normalization makes an immutable equivalent profile
stable. Full original activation and last inspect wires, and the last raw copied
UMRC/URMI fixed352 prefix, are independent diagnostic DATA. A stored prefix does
not assert validation or consumption, and is not a complete body archive.

Submit reserves history BEFORE a real raw call and returns only its positive
full-u64 Gateway ticket after successful output validation. UINT64_MAX is a valid
opaque ticket; only zero is invalid. A successful submission is admission, not a
completed response. Duplicate/reused known tickets or unknown post-admission
outcomes poison and once-retire the known source; no automatic resubmission.
Code11 explicitly means no credit/no dispatch, but still consumes this chosen
local attempt budget. Caller retries, if any, are explicit separate operations.

A server response requires the exact previously delivered Gateway ticket and
separate current responder owner. Mark its local attempt terminal BEFORE the
raw call. Success has no business output; any error remains terminal and is not
permission to send the response again. Native request GUID/sequence stay actual
metadata, never manufactured by reinterpreting this Gateway ticket.

## Whole record, metadata and one successful commit

Before peek, the provider validates actual selected SDK field/width feature,
full stable source/peer/context/receipt, whole output capacity and nonoverlapping
C outputs/state/scratch. RMW C service request writer width16 is the original
current C implementation's explicit supported boundary. The actual compile/link
feature defaults0; missing original fields returns95, no substitute types.
An actual transport Native width mismatch returns95 without consuming.

UMRC160 must be an exact peek reply: magic/version/command/role/backend, full
binding/incarnation/peer, echoed capacity and writer extent, positive accepted
stream sequence and a separate positive attempt nonce, exact record/body bounds,
and zero reserved/other operation fields. Nonce is strictly newer than previously
observed; sequence must exceed the last successfully committed stream record. Client
responses additionally require the original C UWRE binding's contiguous sequence
starting at1, refusing a gap before consumption rather than failing only after
commit.
A failed or unassociated header cannot supply a guessed cancel token: poison and
once-retire the already known endpoint instead.

URMI192 must match the same source/incarnation/stream sequence/Gateway correlation
and exact whole canonical extent. A business request/response needs complete
source/receive timestamp and native request-ID presence, exactly16 actual writer
bytes, actual signed64 native sequence, no topic GID/sequence fields, correct
sentinels/reserved/control bytes and correct client response/server request kind.
Every timestamp/sequence bit, including negative and zero values, is retained;
a complete all-zero writer GUID remains legal. Native/Gateway/RMW-local identity
spaces are independently preserved. The actual C consumer already maps its own
legitimate local request ID back to completion and saves actual native info in
its separate diagnostics.

Resource-error/closed controls contain no invented native info/body. Their actual
error reason, correlation and original retired/external-effects bits are retained
from this same record. A client response callback reconstructs exact UWRE64 plus
whole canonical response, or UWRE64 control with metadata-presence0. It does not
add a second ticket to response body. Request callbacks cannot represent a UWRE
control as a fake request: after one successful control commit they return its
real nonzero reason (zero closed reason maps to125), preserving output objects
and the actual raw prefix in diagnostics.

All body and metadata publication waits for exactly ONE successful commit ACK.
Client UWRE bytes are fully prepared privately first. On success, only ordinary
caller-owned memcpy/assignments follow; no fallible import/allocation remains.
This is a function-level C output contract, not multi-address hardware atomicity
against invalid concurrent aliases. A failed commit is ambiguous: preserve outputs,
poison/once-retire, never cancel as rollback or retry. A metadata refusal with an
associated borrow cancels exactly its sequence+nonce. Preserve primary, actual
cancel, commit and retire codes separately; cancel failure triggers terminal
retirement. Idle11/capacity90/metadata95 retain raw outputs and do not consume.

The real typed Native producer/Gateway must validate complete canonical encoding
before queueing. This provider validates the associated wire and selected extent,
not a made-up C/C++ object layout. Existing original C performs genuine full
transactional object decode afterward; post-consumption decode allocation/error

response tickets and duplicate actual server request IDs are rejected before

Native retirement is attempted once and saved; later C cleanup returns that real
saved outcome. B independently closes BOTH raw owners even when Native retirement
fails. Optional `record_raw_close` is a DATA attachment to genuine pre-fini B
diagnostics, never a close operation/evidence. Keep all original B and Root

must still be drained by raw close and actual Host session/instance retirement.
