# Explicit threaded RMW source profile

This package adds an optional **source-recompiled** dispatch, lifetime and wait implementation to the real `rmw_uwvm` client-library bridge. It is not a replacement RMW header set or a Guest native ABI. Build all original `rcutils`, `rmw`, `rcl`, `rclcpp`, generated type support, platform, providers, adapters and application against the same admitted cross SDK and these exact headers. No old binary layout compatibility is claimed. The original build option is OFF; the former single-thread behavior remains selected in that mode.

No candidate in this delivery has been configured, imported, generated, compiled, linked, probed, executed, or tested. Authored source contracts below are not results. Existing Runtime/HLL threads source integration, previous finite-facade models, and native counterpart markers do not establish this profile's Wasm shared-memory/exception/pthread or ROS interoperability qualification.

## Real process serialization and lock order

`uwvm_rmw_dispatch` is a separate ROS-free static support package. One nonrecursive pthread business mutex serializes the real RMW public calls and both actual capability Sessions (B/C endpoint owners and A Clock/log owners). Every mutable public RMW function acquires that mutex before looking up or dereferencing a registered handle. A lexical GCC/Clang cleanup guard releases it on every ordinary early return. Recursive RMW entry from an application allocator, generated-object codec, provider or platform callback refuses before lookup. The before-lookup refusal returns the public RMW error without invoking a potentially reentrant application allocator to create an error string. Its exact17 reason is retained in preallocated TLS and exposed by `current_thread_last_entry_refusal`; it does not overwrite a Context business primary before that Context was admitted. Actual upstream application callbacks happen after the RMW call returns; this profile does not hold a fictitious lease over an original rclcpp callback.

A platform entry may borrow only actual ownership already established by the same native thread's real mutex guard. It sets a separate implementation TLS platform depth, so nested platform calls refuse without overwriting the outer guard. Public RMW callbacks still refuse. Other threads acquire the same process mutex before using the A Session. A successful retain followed by release therefore cannot spuriously lose its reference merely because another thread is reading a Clock. The old A atomic recursion flag and all explicit platform prepare/retain/release/close obligations remain.

The independent registry mutex is short. It covers actual Context/guard publication, lookup admission for fast notifications, pin counters and logical tombstones. It never spans application allocation/deallocation, native providers, Host imports, physical wait or callbacks. The only lock order is business then registry. Guard trigger and shutdown phase one acquire registry only and release it before physical notification or business acquisition. They never wait for business while holding registry. Concurrent Native operations and their raw Session access remain serialized even across multiple Contexts; the global limit stays eight real Contexts, with the existing fixed per-Context owner/resource/node limits.

The private helper functions now require real dispatch ownership in the ON profile. Their old single-thread test practice of manually setting a scope without a public entry is not a new thread lease. The capability profile and C provider remain immutable through their actual complete lifetimes. ON Node selections require the exact current pin-aware C graph provider callback table. An arbitrary old graph callback is refused95, rather than falsely attesting its registry/wake safety. This finite restriction does not alter OFF behavior.

## Waiting, local notification and physical lifetime

A real waitset reserves fixed storage before exposure. `rmw_wait` admits the entire list and pins its actual Context, waitset, each guard and each endpoint before observing data. A concurrent second wait on that same set refuses17. Different waitsets over disjoint entities and different Contexts may physically wait concurrently. The actual upstream contract forbids concurrent waiting on the same entity in two sets; this implementation detects that case and refuses17 before observation.

While sleeping, the waiter releases its actual RMW scope and process mutex. It retains the real ownership pins. A naturally aligned, lock-free 32-bit Context epoch provides a genuine Wasm `memory.atomic.wait32`/`notify` or Linux futex wait. Notification never resets or wraps: UINT32_MAX exhausts the domain, wakes waiters and refuses further blocking90. The epoch is sampled before the ready predicate, so a trigger between observation and sleep changes the expected word and prevents a lost wake. Spurious wakeups always reenter dispatch and revalidate the actual Context instance, waitset, guard/resource live state, current source and complete native receipt before another observation.

NULL timeout means real indefinite wait. Guard-only waits use no Clock read and can block indefinitely on the actual atomic notification. Waits containing native subscriptions/clients/services use bounded physical one-millisecond slices to reobserve the real provider, since the current transport has no independent asynchronous Native data-ready notifier. A poll count is never called elapsed time. A zero timeout makes one actual observation. A positive timeout requires the separately prepared A steady Clock and explicit existing wait-profile maximum duration/slice/iteration bounds; the threaded atomic driver replaces its uninterruptible `wait_slice` callback. Actual Clock values determine expiration; rollback/error, missing grant, driver-budget exhaustion and notification errors remain errors, never false timeouts. The original C wait-provider callback ABI is unchanged; ON does not call that callback as a fallback.

Endpoint retirement first tombstones public admission. It attempts native retirement and raw owner close independently, exactly once, retaining all original per-owner/native/local result arrays. No old endpoint is reconstructed or replayed. Local object release is postponed until the last real wait pin ends, then runs under an actual business-owned scope outside registry. The new `uwvm_rmw_get_threaded_diagnostics` separates pending local release from an attempted success0. Guard and waitset retirement similarly preserve their real Context child obligation until physical deallocation. Context fini refuses live nodes, children, waits, fast pins, deferred local objects or incomplete shutdown cleanup. No weak pointer, epoch equality or boolean substitutes for this ownership.

A destroyed pinned object makes the waiter return an explicit error without modifying the caller arrays. A successful observation or a measured timeout commits user arrays only after the final fallible platform-reference release. Ready binary guards are consumed only for the returned ready entries. No application buffer or borrowed Native object is retained across suspension.

## Shutdown and original GraphListener

A different native thread may logically close the actual Context and publish local guard notifications without waiting behind a bounded Host request. Same-thread reentrant shutdown refuses17 before this mutation. Phase one is a real atomic close plus a real trigger of the registered live local guards. Phase two obtains dispatch and attempts every retained native incarnation and raw owner once. Operations already admitted before phase one may finish; new normal admission sees the closed Context. This is not a claim that a local mutex can preempt an arbitrary external Native call.

Original `Context::shutdown` calls `rcl_shutdown` before registered shutdown callbacks. Original GraphListener waits with `rcl_wait(-1)` and its callback triggers its interrupt guard before joining. Guard trigger and guard-only wait remain usable for this real notification sequence after logical closure. A Native-only wait on shutdown fails explicitly; it never fabricates a ready message. The original GraphListener source, not a replacement class or success stub, supplies the physical join. Default NodeOptions are not rewritten: an unchanged original Node must have every actual default rosout/parameter endpoint and its complete type/QoS grant, or original creation fails normally.

Allocator/provider terminal traps, asynchronous pthread cancellation, Host cancellation and unknown Native effects require actual Root group/instance drain and physical joins. The lexical C cleanup extension covers ordinary C return paths; it does not make terminal traps safe. No cross-thread mutex token is stored in a transaction or passed to a callback.

## Build and producer boundary

Use three fresh build trees and one admitted prefix, in this order: `threaded/` (`uwvm_rmw_dispatch`), `platform/` with `-DUWVM_RMW_ENABLE_THREADED_PROFILE=ON`, then `cmake/` with that same option ON. The latter two reject a mixed old/new platform composition. The dispatch configure check is function-scoped `CMAKE_TRY_COMPILE_TARGET_TYPE=EXECUTABLE` and genuinely references pthread create/join/mutex, real TLS, lexical cleanup and actual atomic-wait functions. A caller's STATIC_LIBRARY try-compile setting cannot turn it into a compile-only success. This source package has not performed that check.

For WASI use the actual pinned SDK33 pthread toolchain and its shared-memory/TLS/link requirements. Root's fixed SDK primary pins LLVM4434dabb and wasi-libc161b3195 separately; an older wasi-libc source snapshot is not relabeled as SDK33. Root must validate real output imports, exact signatures, shared memory limits, TLS/atomic initialization, memory reservation and selected EH route. Do not add an ambient import exception or infer full original C++ ABI support from a compile-only artifact. Native Linux uses its real futex header/syscall only for local contracts; that is not a Guest fallback. Unsupported targets fail source/configure explicitly.

The caller owns process/cgroup RSS/CPU/disk/deadline limits, all physical pthreads and all Host leases. Build into a new private scratch/prefix outside the SDK; do not overwrite a global compiler home/cache or run network resolution. The machine recipe lists argument arrays and source groups as requirements, with no result fields set true.

## Authored contracts and remaining qualification

`contracts/guard_contract.c` has twelve actual-pthread/original-RMW local groups: infinite guard, pretrigger retention and one consumption, shutdown before join, pinned guard retirement, pinned waitset retirement, same-set busy, same-entity busy, two Contexts, cross-Context refusal, allocator reentry, no implicit Clock, and fini while borrowed. Its explicit deny-open backend is a local model and verifies zero opens, not Host authorization.

`contracts/native_queue_model.c` has six Linux-local groups over actual installed generated String objects: full canonical body plus complete modeled metadata, Native-idle shutdown, pinned retirement with independent native107/raw110 results and no replay, real-monotonic elapsed timeout, Clock regression, and concurrent actual platform Clock/reference/RMW calls with balanced references. Its modeled provider facts are deliberately labeled; they are not real Native GUID/timestamp evidence. Old service full64 correlation, capacity, once-only response and 17-series diagnostic source bodies remain unchanged apart from entry guards and atomic shutdown access. Their old OFF models are preserved separately, not silently retagged as ON tests.

`examples/guest_guard.c` uses the actual ROS2 ABI backend and genuine pthread/RMW APIs, with no capability open. It is a complete Guest-local guard/join example, not native ROS delivery. `contracts/original_graph_listener.cpp` compiles against actual rclcpp headers and starts the real graph listener through `get_graph_event`, then uses actual Context shutdown. `examples/original_graph_main.cpp` supplies a complete explicit two-Clock bootstrap and calls that contract. It uses actual original InitOptions to disable automatic logging and actual NodeOptions to disable rosout/parameter endpoints for this application only. The application additionally calls the original `append_parameter_override("start_type_description_service", false)` API: the selected original NodeTypeDescriptions declares that parameter with default true independently of the parameter-service flags. This explicit local override avoids creating its GetTypeDescription service in this graph-only fixture, whose selection contains no endpoint codecs or native activation provider. No original defaults are patched, and this quiet example is not qualification of unchanged default NodeOptions. The complete executable target must actually link the original SDK; missing original static platform hooks or C++ ABI make that build fail. Its two aliases must be independent real grants; no namespace/env policy is injected. Native topic/service peers, actual Host default-deny/positive grants, complete original executor/threaded signal composition, allocator faults and original SDK shutdown on every selected producer remain required executions.

No graph list substitutes for service availability. No implicit Clock/log/env, debugger, update or management import is added. Missing QoS/status/event/loan/graph functionality retains its existing explicit unsupported result. This profile implements concurrency over the current real RMW capability surface; it does not claim all upstream client-library API support.
