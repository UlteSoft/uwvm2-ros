# Explicit rcljava service availability

This opt-in source cohort implements the original `Client.isServiceAvailable`, `waitForService()` and `waitForService(Duration)` entry points on real capability imports. It is not a native Java/JNI ROS ABI, a graph-list heuristic, or a synchronous business call renamed as observation. All sources and models in this package are unexecuted. Actual Java compilation, TeaVM lowering, Guest import admission, Runtime behavior and native interoperability still require separate execution qualification.

## Grants and owner lifetime

The old `ServiceBinding` constructor retains two independent owners and no availability selection. All three availability methods on that old binding still refuse95 before an optional import. `Profile.denied()` remains authority-empty. Merely naming an alias or implementing a transport interface grants nothing.

The overload with `AvailabilityBinding` explicitly adds a third `service.available` owner. Its Host configuration must contain the real `service-source-alias` paired with the selected `service.call` owner and the same actual native resource, complete native identity, canonical codec presence/value and all eight QoS fields. The observer remains a separate `event.observe` grant paired to the call source and explicitly granting response/error/closed delivery as configured; query rights do not arise from either ordinary role. The optional transport must be explicitly selected. A Clock alias adds a fourth, separately granted `time_read_steady` owner for actual elapsed waits. No Clock capability is inferred from the service or WASI stdio rights.

A closed whole-profile alias inventory rejects optional query/Clock aliases that collide with any topic, service, observer or Clock role. The actual Session owner table is checked for three/four slots before the first native open, and optional ABI1 is checked before opens. The client object, pending/Future slots and every cleanup record are allocated before effects. Opens are call, observer, query, Clock; normal shutdown and rollback close Clock, query, observer, call exactly once. Every returned or thrown cleanup outcome remains in the reserved cleanup chain, independently of the setup primary. Existing uncertain retirement rules remain: an attempted close is not retried or replaced with a new handle. Arbitrary terminal traps/OOM outside executable language paths still require Host drain; this code makes no immunity claim.

`ServiceClient` checks same live Session/backend, distinct complete handles and actual optional transport, then leases both borrowed owners through each synchronous import. The facade also holds its whole-Context dispatch lease for each actual query, feature observation and Clock read. Reentrant close, factory, shutdown or recursive wait from that operation is17. No borrowed pointer or lease survives a completed query into the next checkpoint. The wrapper forwards the original retirement proof boundary to the real ordinary Ros2Transport.

## Wire and time

`Ros2ServiceClientRaw` adds only the independent `uwvm_ros2_client_v1` namespace. Its tuples are the actual ABI catalog: `abi_version()->i32`; `features(i64,i64,i32,i64)->i32`; `service_available(i64,i64,i64,i32,i64)->i32`. The original43 ROS2 imports and the business81 catalog are byte-preserved. Java long retains every i64 handle bit. Memory index is i32; actual Address.ofData offsets are zero-extended to i64 for unshared linear Wasm memory0. This bridge does not accept WasmGC references, JNI addresses or host pointers.

Each real observation creates a strongly retained linear Frame and fills exact output8/output1 with255 before extracting numeric offsets. The import occurs without intervening allocation; the Frame remains reachable through the full copy. Features must be exact7 or explicit0; the factory requires7. The query result must be exactly one byte0 or1. Every nonzero errno propagates as RosException;11/95/110 are never false readiness. Unwritten/short/extra/malformed successful output is22. No business request is sent by these methods.

The current Host/Gateway optional observation path owns an **extra retained native query client**, qualified against the real source configuration. It does not attest that this client is the old business path's native client. A true answer is a genuine native snapshot, not a guarantee that a subsequent request succeeds. Current original-RMW same-object availability is a separate provider path; do not combine its qualification with this facade without a separately reviewed integration.

Duration conversion uses `Duration.toNanos` directly: null and overflow preserve Java failures before query effects. Zero performs one real wait0 observation. A positive timeout uses a separately authorized steady Clock and actual elapsed readings; the signed64 Clock range is explicit and negative readings refuse95. Regressions refuse22. Native slices are bounded by `maximumQueryWaitNs` and the remaining actual duration; no scheduling credit is called a nanosecond. Negative/no-argument waits use the original infinite-wait convention but send only bounded positive native slices. `maximumQueries` is an explicit finite-facade resource budget: exhaustion throws90, rather than returning false or inventing a timeout. A query-only binding without a Clock refuses positive/infinite waits13 before any wait query.

The optional `WaitCheckpoint` runs between completed false observations, outside all import/dispatch leases. It may request Context.shutdown, after which wait returnsfalse without another Native operation. It supplies neither readiness nor time. Recursive wait, executor poll or Future-driven spin during this wait is17. It is a trusted cooperative hook and must not block indefinitely; the caller owns the process/physical deadline. No implicit background Java thread or Native wait set is created. In this single-Guest-thread facade shutdown is cooperative between slices; Runtime physical stop/IPC cancellation is the preemptive path. Each Native call may occupy up to its selected Host-bounded slice, and an uncontrollable Native backend still needs actual process ownership/drain. The existing Java interrupt flag is observed without clearing it; no Thread.sleep or ambient clock is introduced. This does not claim threaded Guest scheduling support.
