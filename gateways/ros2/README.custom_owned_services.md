# Owned native custom Services: additive factory source

This package implements an additive generic typed direct-RCL Service factory,
an independent original-SDK metadata producer/DATA association tool, bounded
complete canonical histories, actual xArm dynamic-value opposite/SDK contracts
and a32-shard source/link recipe. It is SOURCE ONLY. None of its generators,
CMake configure/probes, compilers, linkers, models, native processes, ROS/Guest
commands or SSH was invoked. This is no declaration that all vendors, Native
SDKs, robot/controller versions or Service defaults are qualified. This successor
adds complete modern scalar-default SOURCE support, with no actual SDK or ROS
qualification; arrays/string/nested default literals remain unsupported.

Existing NativeRCL/Registry/owned-profile/Gateway/Host/Runtime files and the old
fixed Empty/Add paths are untouched. The new factory has the actual existing
`native_rcl_service_registry::factory` signature and returns a real endpoint,
not success with an empty owner. The current registry's fixed16 queue limits
and fixed-family admission do NOT automatically call it. The exact explicit
integration seams below remain required before the custom path is reachable.

## Complete compiled identity, not a width/hash-presence bypass

The source-selected original `UWVM_ROS_CUSTOM_ROS2_SERVICE_TYPES(M)` supplies
`M(Native,Name,NativeId,CodecId,RequestCodec,ResponseCodec)` for EVERY registered
selected Service. The paired native provider/common manifest come from the
actual original generator/binder bundle. No Service/vendor table or NativeID
is manually supplied here. Every canonical identity is the actual generated
identity (the original UWVMROS1_ domain also applies to ROS2), not a new guessed
fingerprint. The public header only holds original types, tuple rows, literal
facts and shard declarations; the dispatcher only uses ordinal/function tables.
It never calls the heavy legacy `ros2_custom_services::known` or includes its
non-template inline adapter that mentions every row. Only each selected shard
TU instantiates its modulo32 typed rows; the default partition count is32 and
explicit future builds may choose1..256 consistently for the entire target.

`CompiledCanonicalIdentity<Service,RequestCodec,ResponseCodec>` is a private,
noncopyable proof with immutable owned descriptors and original support handles.
It cannot be constructed from an IPC packet, a bool, a hash read back and called
its own expected hash, or a projected bounded Native schema. Qualification:

1. Associates the actual common root/component descriptors, official type and
   NativeID, generated canonical root/component identities, maximum wire bytes
   and the exact actual Native Request/Response types. Only complete bounded
   generated codecs are accepted. Current canonical component maxima are0..32768.
2. Requires an explicit immutable independent export for EVERY reachable root,
   Request, Response, Event, ServiceEventInfo, Time and nested Message. Every row
   has its original native hash and SHA256 of its complete own TypeSource bytes;
   real implicit empty sources use SHA256(empty), never a fabricated placeholder.
   The view also associates whole actual export and whole independently reviewed
   SDK/MD/ELF/maps receipt hashes. There are NO ready hashes or default export rows
   in this package. Missing actual full export/API is95 before native init.
3. Warms actual generic/introspection handles and requires each actual native
   root/message hash to equal that independently supplied immutable row, along
   with complete exact TypeDescriptions, ordered fields, original capacities,
   exact declared scalar defaults through the private modern branch (or the
   original strict no-default branch), all references and RIHS recomputation of the complete
   proven native graph. Full TypeSource coverage, encoding and bytes digests must
   match all independent rows. All graph rows are unique and connected; bounds
   are256 declarations, depth16,16384 total fields and16MiB raw source per graph
   (4MiB per own TypeSource). It does not interpret nonzero or fixed-width as
   proof. A mismatch is13; unavailable actual API/data is95.
4. Checks actual introspection structure size/field/layout/nested support and
   init/fini contracts, root ServiceMembers, actual typed Request/Response/Event
   handles and exact generic/introspection root associations. Real event
   constructor/destructor functions must agree across those root handles. The
   separate real SDK contract constructs/checks/destroys a full actual Event;
   mere nonnull pointers are not reported as an executed callback proof.
5. Admits only the actual integrated `native_default_variant` scalar grammar,
   with complete modern original generic/introspection TypeDescriptions and all
   independently expected full raw source/identity/layout proofs. Defaults are
   NOT part of RIHS01: equal hash cannot prove a literal or its absence. First
   establish actual root/component/Event associations and callbacks, then all

   only afterwards a PRIVATE layout matcher treats either null or nonnull
   introspection default pointer as UNKNOWN. It never reads/dereferences that

   the entire old no-default `messages` method and proof remainder are unchanged.

## One real endpoint, bounded canonical history, real Native object conversion

The returned endpoint directly owns one actual `rcl_client_t` OR `rcl_service_t`
and retains the original shared Node/rcl_node, actual CPP Registry and immutable
proof. All clients' send/take/query/fini and servers' take/respond/fini use that
same original native object and actual receipt/incarnation. It does not create
rclcpp Client/Service objects, temporary probe clients, alternate middleware or
old81 business fallback. Callers still authenticate/hold the real Host source
and separately paired source/respond/query owners for the whole operation.
Numeric owner fields, copied capabilities, tickets and metadata are associations,
never bearer authority. Default permissions remain empty. Advertise grants no
respond rights; call grants no independent availability rights.

Every history slot, maximum canonical payload slab, private ORIGINAL Request/
Response object, response scratch, encoded scratch, report and object owner is
allocated/retained before actual native init. History1..256 and per-component
wire maxima0..32768 keep payload slabs at most8MiB/endpoint; other object/report/
container storage is additional and must be admitted. History must cover actual
configured max-inflight and QoS depth. The count is a lifetime record bound, not
Native quota and not permission. None of the older16-byte limits is simply
changed globally. IDs/tickets/history/borrow tokens never wrap/reuse; exhaustion
returns90 and needs a new actual incarnation, not eviction/replay.

Native decode is always into a private preowned ORIGINAL generated object.
Canonical validation first checks the entire actual grammar; only then does the
generated complete codec construct all string/sequence/native fields. Bad alloc
is12, malformed/incompatible conversion22; a private object's partial state is
not a public result or native effect. String bytes, strict UTF8, scalar sign/width, array/sequence lengths and nested
objects are complete. This bounded canonical profile explicitly REFUSES NUL;
its nul=forbidden identity is unchanged. Raw builtin String has a different
contract and must not be used to relax custom bounded UTF8.
Actual response storage is retained with unique_ptr swaps, not an unjustified
nothrow dynamic Native copy. Encode verifies the complete actual native value,
active exact size and canonical grammar before queueing/delivery or tombstone
discard. Empty canonical0 still requires the actual original uint8 IDL dummy0
on encode; a missing/wrong-type representation is unsupported95 at admission.

An ORIGINAL unbounded native string/sequence may allocate during middleware
NativeTake BEFORE our post-take canonical bound. The wire bound is not a Native
allocator bound. Same actual schemas/TypeSupport are preserved, so the original
external64GiB cgroup, actual RSS/shared commitments, finite process/phase/final
watchdog and whole descendant cleanup remain mandatory. An in-process clock
check does not preempt foreign init/send/take/fini or allocator code. Native
libraries, immutable identities, proof/CPP Registry and Node must outlive every
object/borrow/callback; all consumers source-recompile against the exact current
codec.h trailing validation_state layout. This is no stable old-binary ABI claim.

A client reserves original lifetime ticket/history/body/object storage before
one actual rcl_send_request. Gateway unsigned tickets, actual signed native
request sequence, actual request writer GUID, URMI stream sequence and borrow
nonce are distinct. Actual zero GUID is valid; no counter is used as a Native
GID. A response is from the exclusive same client take and its actual native
info; unknown/reused sequence, malformed/oversize/wrong value or ambiguous send
is terminal, never permission to resend. Every successful NativeTake value is
fully encoded/validated even for unknown request ID or cancelled/expired late
response. The complete actual native info remains associated with its own
record; signed timestamps/sequence and zero GUID are never fabricated.

Server requests use one rcl_take_request_with_info and retain its full actual
rmw_service_info_t/request_id alongside the canonical body. Respond requires a
distinct same-domain service.respond source and the original retained native
request_id, sets attempted before the one native send, and cannot replay after
error/late completion. Immutable paired type/canonical/resource/QoS must agree.
Full URMI header/body/record facts are checked together. Borrow peek creates a
private complete snapshot and a fresh independent nonreusing nonce; short90 or
metadata95 does not consume/borrow/change output. Cancel preserves the record;
ACK commit is once-only. A lost/late ACK is ambiguous and requires session guard
retirement, not automatic retry. Actual Host write/cancel/retire ledgers remain
separate; this factory does not replace those guards.

One actual native readiness query on the same retained client is implemented by
`available()`, with a distinct authenticated query owner and exact association.
The r2 endpoint overrides the actual now-integrated `available_until` method.
Its complete method body is identical to the retained Positive13 r2 original
source. Zero duration delegates to the unchanged one-query method. A positive

creates neither another client nor a graph domain. Three distinct current source,

The method tries the endpoint mutex, revalidates the same full QoS/GID association
and selected query pair, checks Context/socket/worker/stop state before and after
every native operation, and samples the same retained `rcl_client_t` with
`rcl_service_server_is_available`. It loans the existing domain event only if the

`validate_body(cap,response,bytes,size)` is a light out-of-line companion for the

Each shard defines its own validator, and the dispatcher retains every validator
