# Original ROS2 custom Service adapter: complete typed method partitioning

This is an implemented source-only candidate for the original ROS2 custom Service adapter. It does not change the separately owned RCL service transport, its fixed/generated codecs, permissions, actual native metadata, or either Runtime. The candidate is held in a separate private package pending independent source review and explicit integration. No candidate, generator, compiler, configure step, linker, model, native endpoint, Guest or remote command has run.

## Exact original behavior and coupling

The actual `gateways/ros2/custom_services.h` defines a public `binding<Service,RequestCodec,ResponseCodec>`, an inline `known(cap)` and a session-owned `adapter`. Both private typed methods, `invoke` and `serve`, are defined in that header. The original `known`, `call` and `advertise` expand every row of `UWVM_ROS_CUSTOM_ROS2_SERVICE_TYPES`. Consequently replacing only `known` does not remove all typed Service client/server instantiations from the main translation unit.

The full original public interface stays `ros2_custom_services::known(cap)` and `adapter(Node::SharedPtr)`, deleted copies, destructor, `call`, `advertise`, `respond` and `close`. The public typed binding also stays available. The instance member order stays Node, nested endpoint definition, and the one server map. Shards receive a reference to that same adapter. They do not own another Node, registry, pending map or callback executor.

`invoke` retains its entire original body: actual-QoS API preflight, complete canonical request validation before native decode, request bound, one absolute deadline, one real client, actual QoS comparison, native availability wait, exactly one async send, the local pending-removal guard, wait/get, complete response encoding and independent canonical validation, response bound and final deadline check. No new exception translation, cancellation claim or replay is added.

`serve` retains its entire original body and preprocessor branches. Its original shared Service state, weak state capture, atomic verified gate, genuine Native Request and header captures, complete encode/decode, original deferred-Service API and actual QoS checks, insertion into the same server map and release publication remain exact. Each pending delivery retains the original native Service and received request header. This extraction does not manufacture timestamps discarded by that legacy callback API.

The complete original `binding` body is unchanged, including both full component contracts and the real root TypeSupport/native interface contract. The original constructor, destructor, `respond` and `close` definitions are unchanged as whole source spans. In particular destructor deactivates states before ordinary member destruction; `close` deactivates, erases, then notifies the original Node. All canonical limits, default handling, TypeSupport/hash/schema proof and old errno/exception behavior continue to come from the current actual dependencies.

## Complete table and evaluation order

There is no hand-maintained vendor list or projected row count. A count and the light public dispatch are derived from every original six-field macro row `(Native,Type,Identity,Canonical,Request,Response)`. Only per-shard implementation translation units construct the full row tuple with Native and both codecs. Every row keeps its original ordinal and literal type/native/canonical identities.

`known` still visits every original row in its original order. Every same-type match increments the original unsigned match count and evaluates its typed binding at that point. The selected dispatch returns that exact row's result. The last matching result still occupies `accepted`, and final acceptance stays `matches == 1 && accepted`. Thus duplicate names still fail without skipping evaluations or changing exception order. An unknown type still returns false. No uniqueness prefilter bypasses the original metadata calls.

`call` and `advertise` retain the original `!known(cap) || wrong-operation` check in that order. Their original macro comparisons then route the first matching ordinal through untyped out-of-line dispatch. Private `invoke`/`serve` definitions occur only in the implementation header. Template recursion starts at the selected shard index and advances by the configured shard count. No other shard instantiates that ordinal. Shared event queues pass through moves; the selected original `serve` receives the same owner, without an extra shared callback lifetime.

The dispatcher holds actual function addresses for `known`, `call` and `advertise` from every configured shard. A selected custom target requires all configured shard objects even when some have no rows. Omitting one object must cause an actual future link failure. Empty providers expand no calls to an out-of-line dispatch function, so a default empty/builtin consumer still links without custom Service objects, including unoptimized builds.
