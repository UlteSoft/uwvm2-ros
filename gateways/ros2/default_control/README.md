# Explicit owned default-control Gateway

This source package implements the Native side independently of the Guest
Registry. It does not register a Host namespace, add a policy grant, replace the
old business imports, change NodeOptions, or turn metadata into authority. Every
candidate generation/configure/compile/link/probe/model/test/Native/Guest/SSH
phase remains unexecuted. Root owns the separately reviewed registration and
actual qualification after the complete source composition.

The small C++17 header is `include/default_control_gateway.h`. The implementation
and separately generated actual Native translation units use C++20. The static
CMake target is `uwvm_default_control_gateway`, with alias
`uwvm_default_control_gateway::uwvm_default_control_gateway`. An actual source
consumer adds this directory with its explicit frozen SDK/source inputs and
links the target; there is no ambient installed package or plugin discovery.

## Independent proof and owner

`prepare(identity*,count,shared_ptr<profile const>&)` is cold metadata admission.
The input is the complete exact sorted native-name list with independently
exported actual RIHS01 bytes, associated with the actual SDK producer, source,
static/native libraries, full compiler MD, ELF/maps and loader evidence. This
package does not generate a hash or use an ambient getter as its own expected
identity. `tools/export_native_ids.cpp` is a separate owned Native exporter with
no expected-ID input. `freeze_identities.py` reads its retained packet through
one bounded no-follow regular descriptor and verifies the caller's exact SHA
and complete required name list. Its generated array contains those actual
bytes only. Export DATA/status is not independent SDK or native qualification.

Every selected metadata node is **genuine C++**, including Log and
GetTypeDescription. The Guest's actual C Log/GetTypeDescription objects are
separate objects and separate inspectors. No C object is cast to C++, no C
TypeSupport pointer is relabelled, and no shape/width/nonzero-hash criterion
stands in for full identity. The entire modern generic and introspection graphs
must match independently expected hashes, all TypeDescription root/reference
rows, exact native field capacities/names/defaults, complete source views,
actual typed sizeof/offsets/member types, declared constructor values and
constants. Full Service Request/Response/Event direct pointers, Event callbacks,
ServiceEventInfo/Time and every nested dependency are included.

Only after the whole modern proof does the layout pass treat nullable or
nonnull introspection default pointers as UNKNOWN. They are not dereferenced or
used to prove declared defaults. Native char maps to uint8 metadata; byte/octet
remains distinct even though both have unsigned one-byte canonical storage.
Original raw-source SHA and the exact known official counted getter view remain
separate. Terminal NUL in that view is retained by explicit-length comparison.

Each Profile has a nonmoving private bounded state, address-authenticated codec
descriptors and actual C++ converters. It is reclaimed by shared RAII ownership,
not a sticky Host process singleton. Root's explicit cold factory/bounds
closures retain the actual Profile; every created endpoint retains it again
through actual native destruction. No global alias map or static proof cache
keeps a Profile between server/Source generations. Preparing grants nothing.

## Exact explicit Root loader input

The separately owned Root integration selects the opt-in option
`UWVM_ROS2_BUILD_DEFAULT_RMW_CONTROL_PROFILE` (default OFF) and CLI
`--default-rmw-control-profile ABSOLUTE_TRUSTED_PROFILE`. Its source must compile
the exact generated `default_control_gateway_identity_input.hpp`; that input's
`uwvm_default_control_gateway_input::export_packet_sha256` must equal the retained
actual independent exporter packet SHA. A runtime file contains exactly these
three whitespace-separated key/value rows, using independently selected finite
storage values and the actual64-hex packet SHA:

```text
maximum-entries EXPLICIT_POSITIVE_STORAGE_ENTRIES
history-per-endpoint EXPLICIT_POSITIVE_CANONICAL_HISTORY
export-packet-sha256 ACTUAL_EXPORT_PACKET_SHA256
```

The symbolic rows above are explanatory and are not a runnable profile. To write
a concrete `profile.template.txt` beside the frozen identity header, supply both
`--maximum-entries` (1..65536) and `--history-per-endpoint` (1..256) explicitly to
`freeze_identities.py`. Giving only one refuses before output creation; giving
neither creates no profile. The actual retained packet digest is copied exactly
into the third row. This tool never writes aliases, policy grants or native
identity guesses. These finite counts do not increase Native DDS quotas.
