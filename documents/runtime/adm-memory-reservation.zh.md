# 地址掩码与线性内存预留

一块内存的索引宽度为 `W`，忽略高 `N` 位后，动态地址域大小为 `D = 2^(W-N)` 字节。普通内存的 `N = 0`。初始化器沿 import 和 re-export 找到定义该内存的模块，只向进程预留池计费一次。所有别名共用映射、页大小和标签布局。

当前逻辑长度由 `memory.grow` 改变。数据配额限定它最多能增长到哪里。虚拟预留还包括不可访问的保护区。仅已提交的数据可访问。热更新时尚存活的旧内存也计入进程总预算。

具有 `full` 权限的 LLVM 调试器执行 `dump restore` 时，暂停的模块图继续持有映射，VM 同时准备新一代模块图。自动确定参与者数量时，初始模块图最多可用空闲预留池的一半。每次恢复时，规划器统计池中剩余字节数以及旧模块图的实际映射字节数。新模块图最多可用二者之和的一半，按字节向下取整，同时受实际剩余容量限制。旧工作线程真正退出并完成 join 后，调试器仍可用原句柄核验其身份。在常规 CLI 会话中，新模块图发布、调试器重新绑定完成后，旧模块图的剩余引用释放，其映射归还预留池，供下一次恢复使用。若宿主另行持有旧源码或编译代码的所有者，对应映射仍计入进程预留池。每一代只计算一次各本地定义的内存，包括其保护区和手动指定的数据配额。默认 i686 池供单个调试会话使用时，每一代的预算为 1 GiB。若必要数据及最小保护区超过预算，初始化失败。显式设置 `--runtime-memory-reservation participants` 时按指定的参与者数量规划。专用 WASI Threads 执行模式和预加载原生驱动的会话沿用常规预留方案。

| 决策 | 依据 | 效果 |
| --- | --- | --- |
| 自动配额 | 进程预算、声明的上下限、已存活内存、手动配额 | 按 2 的幂分份，先保证每块内存的最小容量和保护区。 |
| 手动配额 | 本地定义、请求字节数、声明和进程预算 | 小于声明下限时报错。超过声明上限时裁剪并告警。 |
| 全保护窗 | 掩码后的动态地址域、实际预留跨度 | 指令的完整有效范围落在窗内时，可交给页保护检查。 |
| 部分保护窗 | 有效范围可能越过当前预留 | 翻译器需要证明访问合法，或生成边界检查。 |

64 位宿主上的普通 memory32 保持固定完整窗。memory32 忽略 4 位和 memory64 忽略 36 位时，动态地址域同为 256 MiB。memory64 忽略 16 位时，动态地址域仍达 256 TiB，超过 64 位宿主默认的 16 TiB 进程预算。

单次标量访存先对动态地址取掩码，再按加宽精度加指令静态偏移，最后计入整个访存宽度。约 `2D` 加尾部保护区的窗可覆盖小于 `D` 的静态偏移。更大的静态偏移须单独证明。对相加结果再取掩码会产生回绕。批量操作的长度保持整数语义，零长度操作也有规定的边界。

对每个 ADM 数据配额，进程预留池按公共份额分配后能容纳完整窗时，规划器优先选用完整窗。手动配额决定数据容量的字节数，超过声明上限时按上限裁剪。内存仍以 Wasm 整页增长。部分窗需要将有效配额按宿主页向上取整，再加上尾部保护区。若池容量或操作系统无法提供完整窗，VM 会按同一数据配额使用部分窗。部分窗也无法映射时，初始化失败。

以单块内存为例，若动态地址域为 256 MiB、Wasm 页为 64 KiB、宿主页为 4 KiB，尾部保护区为 69,632 字节。给定 536,940,544 字节的池，16 MiB 和 256 MiB 两种手动数据配额都可使用完整窗。给定 384 MiB 或 512 MiB 的池，两种配额会分别使用 16,846,848 字节和 268,505,088 字节的部分窗。

小页要另查逻辑末尾。以 4096 字节的宿主页为例，使用 1 字节 Wasm 页的内存增长到 4097 字节时，偏移 4096 合法，4097 已越界。这两个字节在同一宿主页中，即使地址窗完整，也需要逻辑长度检查或等价的静态证明。MTE 标签检查独立于这项证明。

详细日志逐内存定义列出模块与本地索引、索引宽度、掩码位数、全保护或部分保护、自动或手动配额、别名数、Wasm 和宿主页大小，以及数据、保护区和总预留的字节数。比较不同路径的性能时，保持有效数据长度、负载和访问次数一致，单独计量执行时间。
