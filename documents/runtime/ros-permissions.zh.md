# ROSv2 的授权、观察降权与使用限制

模块必须先绑定到宿主创建的 ROSv2 环境。未绑定的模块无法导入该环境的查询。绑定本身不授予任何设备、驱动、时钟、消息路由或跨模块资源。

## 默认开放的必要查询

- `abi() -> i32` 直接返回公开的 ROSv2 ABI 主版本，当前为 `2`。它使用 VM 认证的当前调用模块身份，无需创建代理、激活提供方或打开资源。
- `permission.report` 查询调用模块自身的名称、所在权限组、接口可见性和适用的权限元数据。它只返回本模块的视图。组成员名单、引用本模块的其他模块、驱动状态和 VM 配置均有独立的授权检查。

这两项属于可降权的观察接口。宿主可用 `--ros-scene-interface robot abi deny` 保留链接并使版本调用返回 `13`，或用 `--ros-scene-interface robot abi hidden` 隐藏导入，让依赖它的模块在链接时失败。`permission.report` 也支持这两个设置，并可单独拒绝一个报告类别或函数。例如 `--ros-scene robot permission.report wasip1.fd_write deny` 阻止查询这个函数的权限，也会拒绝可能泄露同一信息的汇总报告。两项默认查询可分别配置。

## 需要授权的接口

其余接口默认隐藏。操作员按调用模块所绑定的环境显式暴露函数。访问命名资源还需要绑定到具体动作和目标的授权。只读函数也可能读取其他主体或业务数据。例如 `module.importers` 会披露依赖关系，`vm.describe` 读取宿主构建或运行配置，`sensor.describe`、`clock.read` 和 `parameter.get` 都涉及已配置的资源。启用自身观察不会授权这些操作。

## 限制类配置

调用频率、每窗口字节数、容量和等待时间规定授权操作可使用多少资源。限制值不会增删权限。对使用通用调用或字节计量的操作，宿主先验证模块、接口及资源授权，再检查预算。

- 无可选频率限制时，有效授权仍受资源自身的容量和期限约束。
- 本窗口额度耗尽时，普通操作返回 `again`（11）。有正额度的后续窗口可以再次接纳调用。额度显式设为零时，每个窗口都拒绝普通新工作。
- 接口设为 `deny` 或授权被撤销时，调用返回 `denied`（13）。等待预算刷新无法恢复权限。隐藏导入会在链接阶段失败。
- 停止、关闭和清理路径仍检查各自的权限和所有权。具有独立预留容量的清理路径可以在普通流量耗尽时执行。

调试和检查输出中历史字段 `attenuated` 表示该授权已设置使用限制，`revoked` 表示授权已撤销。应分别读取这两个字段。提供方的排队、队列溢出和超时语义见各接口合同。
