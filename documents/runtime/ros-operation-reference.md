# ROSv2 complete operation design reference

Generated by `tools/ros_scene/check_operation_design.py --generate` from the
semantic catalogue and operational contracts. Edit those sources, then regenerate.

This reference specifies all **163 catalogue operations**. A registered
import, an implemented native provider and a qualified robot deployment are separate
claims. Planned operations below are not callable imports or available CLI options.
The named fields are ordered wire fields; the existing special/fixed carriers retain
their exact concrete encoding. No new ABI integer status is introduced here.

See [provider procedures](ros-robot-provider-procedures.md),
[robot capability domains](ros-robot-capabilities.md),
[legacy migration obligations](ros-legacy-coverage.md), and
[implemented CLI](../command-line/ros-scene.md).

## Common rules

### Default authority

No exposed operation or grant by default. Grant only an exact resource/action/profile and actual caller incarnation. Capacity does not imply authority. The sole default exception is read-only permission.report after explicit ROSv2 module binding; it can be hidden or reduced. Foreign observation and registered messages still require independent explicit grants.

### Rate progression

Absent optional rate is unlimited inside an existing grant. Explicit zero denies; stable capacity reservations and independent fault/stop capacity are separate. Attenuation of a control phase requires an explicit qualified missed-phase policy.

### Origin closure

Each supplied capability is checked on its own actual origin. Ancestors, inputs, control owner, active versions, egress and output destinations do not borrow the primary handle permission.

### Effect classification

Classify the complete downstream graph, including ROS topics/services/actions/parameters, callbacks, bridges and native components. Unknown classification refuses effectful activation. Observation or planning never authorizes physical execution.

### Transaction

Validate input/output spans, finite decode/work budgets, selected semantic value schema, current authority and complete reply/recovery/retention before effects. No guest pointer survives the call.

### Concurrency

No authority/provider lock is held while waiting on IPC or invoking an external sink. Commit rechecks original identities/generations. Lock order and compound origin checks are provider obligations.

### Physical execution

Require current ownership/mode, complete physical content validator, original trusted state/dependencies, receiver fencing, independent watchdog and stop reservations at actual effect. Native ACK is not independently observed safe state.

### Allocation

Owning admitted state uses recoverable project fast_io allocation. Null/failure returns before effect; ordinary terminating allocation is not an untrusted admission strategy. Borrowed codecs allocate nothing.

### Limits

Every variable record/list/queue/metadata/pin/process/thread/native workspace has explicit finite capacity. Fixed implementation ceilings are support limits, not portable semantic limits and not silent truncation.

### Lifecycle

Logical close/revoke does not reverse completed effects or free live borrows. Unknown physical/native outcomes retain identity and capacity through qualified reconciliation.

### Observability

Debug/IDE expose cached bounded redacted state/counters/reasons only. They cannot trigger I/O, grant authority, export paths/credentials/payloads, or rearm safety.

### Platform

Native extensions execute outside the VM in a qualified process boundary. Unsupported required isolation/placement/transport/cleanup guarantees refuse activation. No generic WASI or preloaddl fallback.

### Evidence

A schema, decoded record, registered import, native provider, VM qualification, differential ROS case, performance profile and physical assurance are distinct evidence levels.

## Commit, delivery and recovery classes

### discovery

**Commit.** Return the explicitly exposed module major; do not discover hidden imports or provider features.

**Copy failure.** No output memory carrier and no state to consume.

**Retry.** Read-only repeat.

**Retirement.** No resource created.

### capability_acquisition

**Commit.** Resolve an exact existing alias and bind the actual caller incarnation. Publish a new handle without increasing its immutable grant ceiling.

**Copy failure.** Rollback an undelivered new handle.

**Retry.** A repeat is a distinct handle acquisition; it does not reset grant counters or revoke existing handles.

**Retirement.** Capability close does not retire borrowed resources or accounting.

### capability_retirement

**Commit.** Close an owned handle or execute the separately authorized revocation scope; fence further operations and wake affected work.

**Copy failure.** Do not undo an already applied security restriction. Preserve bounded audit evidence.

**Retry.** Apply only the original owned scope; stale/closed identity cannot select a newer incarnation.

**Retirement.** Retained resources, pending effects and cleanup debt outlive logical revocation.

### owned_creation

**Commit.** Validate exact origin/profile closure; reserve the complete admitted object and dependencies before publishing its identity.

**Copy failure.** Rollback unpublished object and its own staged references; do not close parent/source objects.

**Retry.** Without an explicit creation key a repeat is a new acquisition; it cannot implicitly renew a lease or reset state.

**Retirement.** Release only after all retained borrowers, requests and native owners retire.

### asynchronous_creation

**Commit.** Record the owned monotonic creation key, deadline and origin closure before beginning bounded isolated native creation.

**Copy failure.** Retain the same creation receipt; no duplicate native launch from a failed copy.

**Retry.** Exact key and content recover the same creation; changed content conflicts. communication.open.take publishes the endpoint.

**Retirement.** Undelivered/cancelled native owners remain charged until positive cleanup evidence.

### owned_observation

**Commit.** Authorize the complete visible origin and query; snapshot only the requested bounded result. Explicit timed queries may progress their documented provider state.

**Copy failure.** No queue acknowledgement, implicit resubmission or resource retirement from a failed copy.

**Retry.** Repeat the query under current authority; snapshot cursors and generation must match their original filtered scope.

**Retirement.** A read does not erase recovery or physical uncertainty; owned snapshot/page pins have finite lifetime.

### local_mutation

**Commit.** Validate all exact owner/dependency fields and complete mutation before committing within the owning registry.

**Copy failure.** Honor the concrete wire commit point; a failed post-commit copy is not automatic rollback. No external hardware effect is permitted.

**Retry.** Use original offset/generation/sequence where provided. Unkeyed operations do not promise exactly-once replay.

**Retirement.** Only owned local state changes; held references and sealed content retain accounting.

### bounded_wait

**Commit.** Reserve bounded output/wait capacity, release authority locks before waiting, then recheck current authority and the exact observed horizon.

**Copy failure.** Do not consume readiness, messages or native acknowledgements on bad output.

**Retry.** A repeated wait observes current state; it never republishes a message or creates an acknowledgement.

**Retirement.** Cancel/shutdown wakes waiters; elapsed time never fabricates provider support.

### consume_after_copy

**Commit.** Reserve a whole owned item and its original metadata/correlation. Copy and revalidate before marking it delivered or advancing the queue.

**Copy failure.** Retain the same item or explicitly retire it only under revocation/deadline policy; failed copy cannot consume silently.

**Retry.** Retry delivers the retained item while its original authority and lifetime remain valid. Duplicate successful consumes are not exact replay.

**Retirement.** Pins and correlations survive logical handle close until their real borrower/recovery obligations finish.

### owned_close

**Commit.** Fence new work on the exact owned resource and apply its documented drain/cancel/safe-release policy.

**Copy failure.** Preserve already-applied closure; close never resets budgets or reopens a source.

**Retry.** No handle reuse or closure of unrelated sources. Already-retired identities remain invalid under the concrete binding.

**Retirement.** Delay capacity release until borrows/native work/processes actually retire; physical unknown outcomes remain latched.

### keyed_effect

**Commit.** Decode the complete operation, validate original authority and secondary origins, and reserve reply/replay/effect capacity before recording the accepted request and crossing an effect boundary.

**Copy failure.** Keep the same accepted receipt and any unknown effect; no automatic resend after failed delivery.

**Retry.** The exact original key and contents recover the retained receipt. Modified/out-of-order requests fail. Underlying native atomicity and cancellation are never inferred.

**Retirement.** Retain input pins, native correlation and cleanup/unknown debt through terminal evidence or qualified reconciliation.

### owned_cancellation

**Commit.** Fence only the owned pending request or local response interest; native cancellation exists only when the selected provider explicitly supports it.

**Copy failure.** Keep the observed cancellation receipt; do not convert lost output into another remote effect.

**Retry.** Repeat observes the same owned request; abandoned service interest is not remote cancellation.

**Retirement.** Already crossed effects remain represented and charged until qualified resolution.

### callback_response

**Commit.** Require the exact delivered owned callback, current generation and deadline, legal response and any independently granted transformed values.

**Copy failure.** Preserve exact response recovery where the concrete provider defines it; never call guest code from a native callback.

**Retry.** Only the matching original response can replay; conflicting transformed content or callback incarnation is rejected.

**Retirement.** Resolving a logical callback neither rearms a device nor proves an external effect completed.

### lifecycle_submission

**Commit.** Commit only the next successful key, expected generation, legal transition, permitted mask and finite deadline; queue one guest callback.

**Copy failure.** Retain the same five-word logical receipt.

**Retry.** Exact last successful submission recovers its receipt; rejected requests do not consume keys.

**Retirement.** Deadline enforcement of the local binding is on access; no autonomous physical watchdog is implied.

### receive_reservation

**Commit.** Reserve the exact complete owned delivery and expose its identity/metadata without acknowledging native consumption.

**Copy failure.** Retain the original item/identity; do not leak a partial new reservation.

**Retry.** Only the same live reservation and owner can be acknowledged or released.

**Retirement.** Reservation capacity remains charged until acknowledgement/release or qualified provider retirement.

### receive_acknowledgement

**Commit.** Acknowledge only the exact current owned reservation after its checked delivery contract.

**Copy failure.** Do not acknowledge a different item or repeat a native effect because output failed.

**Retry.** Idempotence is scoped to the concrete reservation identity; stale identities cannot consume a newer record.

**Retirement.** Release only this reservation and its retained correlation according to provider rules.

### receive_release

**Commit.** Release the exact owned reservation without implying remote application completion.

**Copy failure.** Do not alter unrelated queue entries.

**Retry.** Exact ownership and reservation incarnation remain mandatory.

**Retirement.** Return or retire only that item according to the explicit receive policy.

### cache_transaction

**Commit.** Use the per-alias successful next key and exact receipt reservation. Reserve the entire object; publish only complete immutable session content.

**Copy failure.** Preserve the same nine-word receipt and allocated object; no duplicate append or mutation.

**Retry.** Exact last request replays; the next successful mutation acknowledges the prior receipt. Status/read calls do not acknowledge.

**Retirement.** Volatile publication is not durability. Borrowed published content and incomplete transactions remain charged until actual retirement.

### recording_transaction

**Commit.** Validate channel/source read and export authority; commit complete bounded records/checkpoints under the writer key and owned source pins.

**Copy failure.** Retain exact receipt and checkpoint identity; no partial record publication.

**Retry.** Exact writer-key replay; record ordering and source generation remain unchanged.

**Retirement.** Current checkpoints are volatile MCAP objects; readers retain them independently of writer closure.

### proposal_pipeline

**Commit.** Capture authentic ordered inputs; authenticate a completed model result; independently admit the exact target action and its original origins at acceptance. Each stage requires its own grant.

**Copy failure.** Keep its exact keyed record; no model output or failed copy may manufacture a target invocation.

**Retry.** Exact stage keys only; changed model bytes, target, input order/digest or source incarnation conflict.

**Retirement.** Capture/model/proposal pins remain accounted; acceptance never transfers or expands authority. Current target support is independently qualified.

### bounded_logging

**Commit.** Check the exact logger/severity/session sequence and explicit content budget; append inert private text without format-string execution.

**Copy failure.** Keep the actual accepted/lost state, never claim durable audit storage.

**Retry.** Concrete session sequence controls duplicate handling; a loss counter cannot create execution authority.

**Retirement.** Bounded logging loss is observable and cannot consume independent stop/fault capacity.

### terminal_release

**Commit.** Retire only a terminal owned recoverable receipt whose native cleanup and borrowing obligations are complete.

**Copy failure.** Never forgive unknown effect or release a different request.

**Retry.** A released identity cannot refer to future work.

**Retirement.** Unresolved outcomes and cleanup debt block capacity retirement.

### robot_provider

**Commit.** Apply the operation-specific admission/effect/recovery rule in robot-provider-contracts.json; required native guarantees must be positively available before activation.

**Copy failure.** Apply that exact operation rule; never treat a decoded response as trusted physical evidence.

**Retry.** Resource-scoped strict next key/exact replay for keyed mutations; inert opens roll back on delivery failure; unkeyed observations do not execute work.

**Retirement.** Stop and unknown-effect reservations remain independent and survive logical closure.

## Canonical named records

These definitions apply to canonical/proposed record carriers. Raw fixed-word
artifact/lifecycle/runtime formats are specified by their concrete contract headers.

### request_key

`session: u64`, `sequence: u64`

Session is an owned live endpoint identity; sequence is monotonic and ledger checked before effects.

### stamp

`clock: u64`, `epoch: u64`, `nanoseconds: i64`

Clock identity/epoch must match the associated source; security deadlines use steady host time.

### profile

`identity: text`, `digest: bytes`

Exact immutable deployment-approved identity and digest; no URL, path, native symbol or arbitrary option bag.

Digest is exactly 32 SHA256 bytes of the immutable canonical registry descriptor.

### endpoint_request

`node_capability: u64`, `node: u64`, `schema_capabilities: array<u64>`, `profile: profile`, `resolved_name: text`, `type_identity: text`, `role: text`

Resolved name/type/role must match approved profile after remapping.

Node capability must independently authorize this exact owned node. Schema capabilities are ordered exactly like the immutable profile: topic 1, service request/response 2, action goal/feedback/result 3. No capability is opened or inferred from an alias or resource number.

### message

`type_identity: text`, `encoding: text`, `body: bytes`

Approved schema and encoding; recursively bounded decoder and content checks before effects.

### metadata

`source: u64`, `generation: u64`, `sequence: u64`, `source_stamp: optional<stamp>`, `received_stamp: optional<stamp>`, `publisher_identity: optional<bytes>`, `loss_count: u64`

Unavailable native fields remain absent; no fabricated receipt/ordering data.

### delivery

`metadata: metadata`, `correlation: u64`, `kind: text`, `message: message`

Role-specific kind and schema; record committed only after complete checked copy.

### receipt
