ROS1 `param.search` retains fixed exact-name behavior by default. The optional
`search-parent-namespaces=true` field adds only the same fixed basename in
ancestor namespaces, constrained by `allowed-name-prefix`. Worker validation,
CLI capability assignment, Gateway configuration, and the native candidate
walk all recognize this explicit boolean only for ROS1 `param.search`.
Missing/false fields retain old exact-name behavior, including grants with
broad prefixes. The new field is part of the existing immutable policy
manifest; no ABI export or request encoding changes.

The shared C++17 helper checks candidates before each native `hasParam` query
and validates returned search names again in the Worker. A neighboring prefix
denies the initial resource before any query. An allowed walk stops at its
prefix boundary and returns 2 without revealing an outside ancestor. The
Gateway checks one absolute deadline before and after each native call; this
does not establish interruptibility of a blocking XMLRPC phase. Configured
root `/` search resources remain rejected by the existing configuration
validators. The helper's defensive root case has no parent candidates.

The fixed-basename projection supports the native upward-search ordering for
a single relative component. Native multi-component relative search has
additional partial-match semantics and remains outside this projection, as
explained in the [scoped contract and test guide](../../tests/ros1_search/README.md).
The SDK ABI remains usable with the existing empty search request. SDK guides
that describe only exact lookup require a corresponding conditional-parent
note before a new SDK source bundle is frozen.
