# Complete official Header / JointState source candidate

This is an unexecuted `/tmp` source candidate, separate from the current repository and Source64. It implements an explicit `uwvm-ros-official-standard-bounded-v1` mode, preserving the existing `uwvm-ros-custom-bounded-v2` restrictions and generated canonical identity domain. It does not rename or project an official field, derive an MD5/RIHS value, register an entity at runtime, grant an alias or add a Guest import. Six-language source generation, native exporter execution and all tests remain unexecuted.

## Implemented behavior

The new mode allows exactly the first official standard family: ROS1 `std_msgs/Header` and `sensor_msgs/JointState`; ROS2 `std_msgs/msg/Header`, `sensor_msgs/msg/JointState` and `builtin_interfaces/msg/Time` / `Duration`. Other standard package names remain refused, including existing Runtime builtin adapter types. Ordinary separately acquired custom model types may reference this exact dependency family. Complete Header fields, timestamp representation, names, position, velocity and effort arrays remain present in declaration order. Each dynamic field still needs an explicit finite canonical capacity no larger than its actual native capacity. No source field is silently truncated.

Catalog entries use `registered:false` for Message dependencies. Header and Time/Duration can never opt in as Topic endpoints in this mode. The generated manifest and native provider macros publish only registered interfaces; complete dependency codecs/schemas/native converters remain available. The only newly allowed standard endpoint is the exact JointState name in the selected ROS major. An internal `official_standard` descriptor marker is set only by the trusted generated source. `custom_topic_name` itself retains its complete original implementation and reserved-package rejection. The new registry branch requires the exact JointState name, the marker and a full bounded schema; String, Bool, Twist, Image and other existing builtin identifiers cannot use it. This is a source ABI extension compiled consistently into Runtime and Gateway, not a Guest/wire ABI or permission extension.

The existing bounded generator emits C, C++, Rust, JavaScript, AssemblyScript and TinyGo complete records. In the explicit mode it additionally rejects nonnormalized nanoseconds and enforces that every nonempty JointState name/position/velocity/effort array has the same length. Empty optional arrays remain empty, including the all-empty case. These complete-value conditions are included in the new canonical identity domain and applied by the Guest codecs and native converters before output publication. The finite-float rule remains unchanged; sensor sentinel support is a separate required implementation item in the gap ledger, not claimed here.

ROS1 unqualified `Header` resolves to the actual `std_msgs/Header`, matching [the official genmsg resolution rule](https://raw.githubusercontent.com/ros/genmsg/noetic-devel/src/genmsg/msgs.py). `time` and `duration` retain their native primitive spellings in ROS1 Definition comparison. Their internal canonical helper records are converters for actual `ros::Time` / `ros::Duration`, whose [time](https://raw.githubusercontent.com/ros/roscpp_core/noetic-devel/rostime/include/ros/time.h) and [duration](https://raw.githubusercontent.com/ros/roscpp_core/noetic-devel/rostime/include/ros/duration.h) C++ fields have different signedness. Generated static field traits compare those actual C++ types; no synthetic message name, native MD5 or MSG dependency section is invented. Their value converters emit an explicit empty C++ native-identity string; a missing Message identity is never emitted as the invalid C++ identifier `null`. The existing Time and Duration source-policy cases inspect their isolated actual primitive-converter emission without inventing a native MD5. Invalid nanosecond values are refused rather than silently changed. The original custom catalog mode still rejects these newly recognized source spellings.

The ROS1 Gateway Definition parser now understands these two native primitives and the exact Header alias. Its comparison remains complete: actual root MD5/type, all declared fields, dependency sections, duplicates and unknown data are checked. Existing positive native traits/hash checks remain intact. The new finite standard dependency names are allowed for declaration comparison; this does not make them endpoints. ROS2 retains the existing complete TypeDescription/introspection/schema and actual hash checks. The actual exporter and native roundtrip source separately compare the installed Header, Time and JointState native identities to the generated values before any future transport acceptance.

## Source paths and mode wiring

The candidate modifies six existing source paths, all preserved before-images from the actual Source64 MF:

- `sdk/tools/custom_types.py`: selects the same trusted bounded source generator for the new exact format.
- `sdk/custom-types/bounded_profile.py`: complete standard dependency parsing, normalization, unchanged custom-mode fallback, six-language/native emission and registration filtering.
- `src/uwvm2/imported/ros/ipc/custom_type.h`: internal descriptor marker and finite JointState-only registration branch; original custom-name function unchanged.
- `gateways/ros1/custom_topics.h`: complete Definition comparison for native time/duration and Header spelling.
- `tests/ros_custom_types/bounded-v2/bind_catalog.py`: accepts the explicit new format while retaining exact original official interface/component identity inventory; markers are copied, not rights.
- `sdk/custom-types/combine_catalogs.py`: combines actual independently bound catalogs into the same explicit format when any input uses it. ROS1/ROS2 type identity keys remain separate; duplicate interfaces still refuse rather than guessing a winner. Mixing into the explicit new mode re-emits its canonical identity domain for the complete combined bundle; an old policy/codec identity cannot be silently reused.

`files/tests/ros_custom_types/official-standard` adds unbound complete declaration fixtures, exact source catalogs, an actual official native identity exporter, sixteen injected source-policy cases, a native full-value roundtrip contract, a real generated-registry boundary contract and a C++17 CMake build entry. Fixture declarations are transparent transcriptions for source tests, not a claim that immutable upstream sources or an installed SDK were acquired. Their original upstream URLs are listed below. Actual model preparation must retain the independently acquired original definitions/license/revision and the original native exporter/owner evidence.

The separately preserved vendor foundation r3 wiring consumes both exact formats through its actual `prepare` → official exporter → strict binder → six-language/native generator implementation. It requires the real current-MF module to implement the standard mode before writing output. Its planner permits a Topic alias only for an actual registered `.msg` catalog entry, so dependency records and Service/Action components cannot masquerade as supported Topics. The independently closed r2 foundation remains immutable. The r3 wiring is a source successor, not a claim that the mode was already installed or run.

## Native identity and execution requirements

`native_identity.cc` retains the actual bounded-v2 metadata helper namespace unchanged. Its fixed new inventory exports installed Header and JointState, plus the actual Time Message on ROS2, after SIGSTOP and the original bounded `I` gate. Native IDs come from official message traits or type-support metadata. This tool creates no ROS Node or endpoint. Compilation must use the genuine installed SDK, original compiler/frontend, full system-inclusive MD, actual native ELF/library trace and owned stopped process maps. Older ROS2 SDKs without the real metadata APIs need the separately listed compatibility implementation; no missing hash is fabricated.

The CMake source defaults to identity-only preparation and never runs a target automatically. A second fresh configuration with `UWVM_STANDARD_IDENTITY_ONLY=OFF` and the actual `UWVM_STANDARD_GENERATED` builds the two real native contracts. The requested full MD/MT, link trace and assertion flags must still be checked against actual original verbose commands and consumed files; CMake options alone are not evidence.

Bind each backend's actual exporter output with the modified strict binder. Combine backend catalogs if a dual profile is required, then run the real current generator. All native-registry source emission still requires caller-exported identities for every catalogued official Message. The Header/time helper types are not substitutes for identity qualification. Build the Runtime and Gateways from the same actual generated manifest and original source/SDK closure. Explicit policy is empty by default; even a compiled supported JointState type creates no alias or native ROS entity.

`native_roundtrip.cc` must be linked against the matching real ROS native type support and actual generated `native_ros1.hpp` or `native_ros2.hpp`. It checks actual installed native IDs, preserves all Header/time/joint fields, roundtrips optional arrays, refuses a trailing byte/nonnormalized nanos/mismatched nonempty lengths, and checks unchanged destinations/output on refusal. It uses actual native structs, not stand-ins, but it does not create a ROS participant or prove delivery. `registry_contract.cc` requires the actual newly generated manifest; it checks selected JointState lookup, dependency non-registration and existing builtin name protection. Both contract sources are uncompiled and unexecuted.

`test_profile.suite(parent, bounded, *, fixture_root, out)` exposes sixteen authored pure source-policy cases. Root must inject the separately admitted actual candidate definitions and an explicitly owned scratch directory. The suite can generate temporary codec source only within that scratch when Root later runs it; its cleanup removes only its own exclusive test directory. It does not compile, run a Guest or obtain a native identity. This author performed only source writing, hashes, JSON/AST reading and source comparisons.

Future acceptance must additionally compile all six actual Guest outputs, validate actual imports/exports/target and full SDK dependencies, run fresh default-denied/positive native routes, compare complete canonical values against an independent native peer, and prove bounded ownership/revocation/disconnect/cleanup. Those results are separate from these model/native component sources and original vendor official suites. No original failure report or frozen Source64 byte is rewritten.
