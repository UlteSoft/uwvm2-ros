# Genuine LLVM-full management lifecycle witnesses

These are new source-authored witnesses. No file in this package has been
compiled, imported, assembled, executed, or used to qualify a provider while it
was authored. Existing Source53/54 native components and DATA models remain
separate results: a local retirement hook or an empty Runtime reset does not
establish an actual generated-code replacement or an active Guest drain.

`management_runtime_contract.cc` now implements the missing native execution
path. It loads the actual assembled ROS1 or ROS2 fixture with
`prepare_owned_full_cli_source(true)`, including two independently initialized
preloads of the same source image. The initializer retains immutable bytes,
parses the three actual instances, and produces the real canonical full source.
The test requires an actual current native LLVM engine for every assigned
module, matching physical Runtime/Host and actual LLVM provider objects, and
the instruction call-stack policy. Neither an Interpreter Worker, an empty
LLVM archive, a native identity stub, a guessed entry pointer nor a numeric
module label substitutes for those prerequisites.

The three instances are `management-main`, `management-other` and
`management-cold`. The native test configures finite explicit Single policies
through the real launch-policy APIs before the source is published. Both
global defaults remain denied. Only genuine generated `capability_open` calls
create the first two Host registrations; the third has never made a ROS call.
The main and unrelated entries are invoked independently through the actual
full-entry ABI, with no cross-module wrapper pretending to be the principal.
Native management calls always verify that they have no primary ROS identity.

The production controller supplies actual emitted before-nop breakpoints and
captures the complete stopped cohort. At the first real stop, the test sends
three real replacement commands: a malformed body, a stale function generation,
and an otherwise valid body for the currently active function. All must reject
without changing the canonical stop or retiring either instance's authority.
The resumed original generated caller then opens/closes another capability and
executes original value `7`. Reaching the second emitted stop proves those
actual Guest assertions completed.

At the second stop, the controller really prepares and commits a same-ABI
replacement of the inactive value function, changing `7` to `9`. A static native
observer forwards the production Host hook unconditionally and observes the
actual old Runtime epoch. The test attaches a local queued event and a real
credential-checked Unix client only to the already Guest-created Host owner.
The first real local stream must contain nonzero queued and pending depth and
bytes. A separate, genuinely configured response stream reserves request23 with
128 response bytes plus32 request-owned bytes; its baseline must have exactly
one uncompleted reservation and160 reserved bytes. The full backpressure stream
cannot supply that witness because a pending record correctly refuses a new
reservation. No fake statistics or completed/cancelled credit is substituted.
The local peer acknowledges the genuine hello and accepts no later RPC. Before
the actual controller acknowledgement is consumed, the target must be an inert
tombstone, the local peer must receive EOF, and all queued/pending/reserved
payload bytes and pending request identities must be gone. These explicit local
fixtures prove descriptor/queue cleanup; they are not a ROS Gateway or network
message-delivery result.

A second genuine private transaction is compiled before that first publication
and retained without changing code or authority. After the actual Guest joins,
the native manager acquires a genuine empty-cohort pause ticket and attempts
that same prepared transaction under the actual `while_stopped` mutex. The
commit must reject its now-stale original generation, preserve the inert target
and unrelated live authority, and leave queues/descriptors retired. This is an
actual failed Runtime commit, separate from the three refused controller
commands and from a guessed invalid token. The token is then discarded and
the empty cohort resumed.

The target module's old handle must fail. Its unchanged functions must also
reject new opens with error `13` and leave the original output sentinel intact,
while its replaced function really returns `9`. The unrelated actual instance
must retain its old and new handles and still return `7`. A second real commit
changes the initially-cold instance's value function; it must allocate no Host
state, execute value `9`, and refuse its first-ever ROS open. This checks the
Runtime-level permanent retirement flag rather than relying on an existing
Host tombstone. Fresh authority is tested only after a genuine reset and a new
explicit trusted launch, never by resetting or regranting a retired record.

The final Runtime is launched afresh. Its genuine Guest opens two handles and
parks at the real emitted breakpoint while retaining its actual execution
entry. The native manager calls `reset_runtime_state_host_api()` with no
publication lock, stopped-domain guard, Host lock, authorization lease or
import/execution callback on its own thread. The production central reset
closes the debugger domain, releases the parked Guest, and drains the real
execution entry. That Guest must successfully close its second real handle
before returning. The forwarded old-epoch callback must then see the first
handle still live and the second already closed, clear the actual Host, and
observe the old epoch both before and after cleanup. Only after reset returns
may the epoch equal old+1. The genuine Guest result must be `42`; the old
controller must be closed and old handles denied. Restoring the exact original
production hook and performing a second genuine reset must inherit nothing.
A native 30-second watchdog bounds synchronous reset; the external Root owner
must independently bound the entire child and kill/reap only its held birth.

## Actual DAP and authenticated control path

`management_runtime_dap.py` exposes
`exercise(frame, load, console, *, backend, module, invalid_body, value9_body)`.
It does not create a process, console, broker or mocked reply. Root supplies the
real `integration_runtime.Control` attached to its already owned, physically
qualified LLVM Worker and the existing inherited private `SOCK_SEQPACKET`
endpoint. That transport checks every packet's actual PID/UID/GID credentials;
its original pidfd/birth/cgroup owner remains responsible for termination and
normal `Frame.finish` after success or failure. Root owns the launch wrapper;
the callable must not be credited unless actually called on that real process.

Before any Adapter load, the callable independently requires the real connected
lane and supplied Frame to select the same physical source path and identical
actual complete-manifest SHA256. An admitted older lane cannot borrow a new
Frame's source label through this interface.
The callable loads the current production `tools/debug/dap_adapter.py` through
the same complete-MF loader. Its output buffer records actual production DAP
frames, not mathematical responses. The broker request method forwards to the
real credential-checked `Control.ask`, as in the existing integration witness.
It installs the two real breakpoints before resuming `_start`, gets genuine
stack-frame and ROS-scope references through real DAP handlers, sends an invalid
replacement, and requires both references to be refused. The actual authority
rows and Runtime stop must remain unchanged after that rejection. The real
Guest then reaches the second stop. A successful real replacement must refresh
the complete stopped identity, refuse previous DAP frame/scope/stop references,
and report the main module retired, disconnected, and without live handles.
Finally `_start` must actually exit zero after running its original unchanged
ROS functions, stale-handle denials and value `9` assertions. This path proves
real Adapter/controller integration separately from the native test's module
isolation, local IPC fixture and active-reset assertions.

The DAP callable retains real command/reply and DAP packet observations and
checks at most 180 active seconds. It loads no project module through ambient
`sys.path`. A live process check, source-bound replacement bodies and a current
MF-loaded adapter are mandatory. No future provider, successful report, PID,
namespace or file identity is forecast in the recipe. A disabled namespace,
arbitrary nonzero exit, malformed status or Interpreter receipt earns no credit.

## Root execution requirements

Use `management-runtime-recipes.json` as a closed source recipe, not an executed
configuration. First build the real reviewed patched LLVM provider and the
current `build_runtime.py` three-profile LLVM-only/no-Interpreter Runtime set.
Keep each profile's actual complete input-root catalogs, full-MD records,
objects, compiler/linker/provider libraries, response files, link trace and ELF
evidence. Native test linking must reuse only the selected profile's actual
Runtime and Host API objects; it must omit that Worker's main translation unit
and compile this test as its genuine main. Include the same current headers,
target/stdlib/ABI, profile defines, real LLVM headers and actual link closure.
Assertions remain enabled. Root must check the test source and production
headers were actually consumed by full `-MD`, and every linked object/library
appeared in the actual trace. There is no SDK or Runtime stub in this recipe.

Use the selected real `wat2wasm` to assemble the two business fixtures and the
replacement reference module. Independently inspect the replacement Code
section: its complete bodies including local-count bytes must be exactly
`0041090b` and `00010b`. The deliberately malformed `00ff0b` is a rejection
input, not an allegedly valid assembled body. All tools/source/artifacts and
owned replacement files need actual current pins and preservation. `_start`
is function index10; the two real imports use the actual ABI
`capability_open(i32,i64,i64,i64)->i32` and `capability_close(i64)->i32`.

Execute four native routes in fresh processes: ros1/ROS1, ros2/ROS2,
dual/ROS1 and dual/ROS2. Execute the same four independently launched Worker
routes through the DAP callable. They are native Runtime integration routes,
not eight official ROS tests. The `none` profile is excluded because it cannot
prove the lifecycle of an enabled business registry. Record unavailable LLVM,
unsupported/failed compilation, missing provider closure, timeouts, signals,
assertion failures and incomplete cleanup as unqualified. Root's original
64GiB/swap0 current-incarnation guard, eight-GiB physical backing reserve,
bounded serial compiler/process owners, exact complete source/input roots and
normal terminal cleanup/preservation remain mandatory. Source58 and all old
failure reports remain immutable. No network/robot/physics/VTune or complete
official-suite result follows from these witnesses.
