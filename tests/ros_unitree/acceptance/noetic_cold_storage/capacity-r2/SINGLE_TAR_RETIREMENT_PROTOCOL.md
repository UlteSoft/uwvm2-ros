# One decoded diagnostic: required proof before any Root retirement

This is a source plan and an incomplete control template, not an executable
retirement owner or deletion authorization. Root remains the sole executor.
The exact target is the one `data.tar` named in
`single-tar-consumer-closure.template.json`. No upstream snapshot, SDK, compiler,
Runtime, compiled product, active output, report, command log or ledger is a
retirement candidate under this protocol.

The genuine diagnostic report's historical full7 expects829,286,400 bytes and
SHA256 `62d549d5b32f81804d50c1ba98bca414ce72333a76aa285dd51dc0c0569d2c81`.
Root observed current device81/inode576860, mode0600/nlink1 and both timestamps

`target_historical_full7_expected` is historical, while `target_actual_full7`
is deliberately null. Constructing an actual-looking full7 by attaching the
old SHA to freshly observed stat fields is forbidden.

Before an archive can qualify, Root must stream the complete currently opened
ordinary file, bracket descriptor and named-entry facts, and record the **new
actual observation**. Its full size/SHA must equal the separately recorded
historical expectation; its actual identity must equal Root's selected current
metadata. No old cgroup/process continuity is inferred. Source and report
full pins are checked again before/after emission and immediately before the
separate retirement. A mismatch leaves the original file untouched.

## Fixed five-role consumer closure

The template fixes these roles: Noetic r6d, Typed r6, CP3, Native74 and Worker37.
All five are mandatory; empty pins/roots or omitted role evidence are incomplete,
not successful checks. Root fills the actual current controls/configurations,
source implementation bindings, selected product receipts, finite file pins,
whole-root catalogs and literal/resolved aliases for each role. No future pin
is forecast. The template fills only already observed Noetic selections; the
other role evidence remains unqualified until Root supplies actual facts.

For each role, follow its exact schema and reviewed source accessors. Close
the selected controls, explicitly consumed report/receipt fields, compiler
dependency/provider inputs, SDK/model roots, executable and shared-library
selections and configured mount aliases. A historical path appearing in raw
provenance is not automatically a currently reopened file. Conversely, omitting
a selected finite file because it is outside the27 Noetic roots is incorrect.
Any additional live or planned consumer must be explicitly resolved before
retirement; the fixed list is a required minimum, not an exception for others.

Reject lexical overlap in both containment directions and physical overlap
after root-sensitive resolution: selected symlink targets, bind mounts, chroot
logical paths, mounted provider copies, and same-device/inode file aliases all
matter. Distinct independent CoW inodes are not hardlink aliases. Unknown or
uninspectable alias classes block retirement. The original whole r1/r4/r5
download roots, original42-file model-DEB tree, r5/sdk and new41-file view remain
complete and online. Keep the small diagnostic report, command ledger and log.

The known r6d source path does not select this standalone tar. The historical
r4 launcher reads the diagnostic's small report and command/proof fields only.
R6d hashes that old CODE directory as data rather than executing its launcher.
This narrow source observation does not substitute for the other four roles'
actual current control closure.

## Active process absence is physical and root-sensitive

Root must take complete, bounded, repeated process snapshots of the owned
cgroup and descendants, and close any other visible live task that might hold
the target. Use pidfds plus same-birth identity and membership checks; numeric
PID reuse or a disappearing `/proc` entry is not absence proof. A racing exit
is accepted only after the held pidfd proves that same process exited. An
unreadable process, truncated set, unknown namespace or unbounded descriptor
set prevents admission.

Inspect every required live process's `cmdline`, `cwd`, `root`, `exe`, complete
`maps`, file-backed `map_files` and `fd` entries. Interpret logical/relative
paths using that process's actual root, cwd and mount namespace. A display name
or substring comparison alone is insufficient: compare actual descriptor or
mapped-file device/inode to the selected current target. Cover renamed/deleted
display suffixes and alternate bind names. Foreign cwd or directory descriptors
inside the diagnostic parent also block, because they can support a relative
open. Ordinary filesystem root `/` alone is not evidence that every process
currently uses every file; actual path resolution and physical handles decide.

All foreign live processes must be absent from the tar path/aliases/handles.
The archive/retirement owner necessarily opens its own source descriptors;
either close them before the global absence scan or record only its exact
same-birth pidfd and exact descriptor numbers, revalidating their physical
identity and purpose. There is no foreign-process exception. Take another
complete absence/control/mount snapshot immediately before unlink. Root must
freeze new unreviewed consumers and target-capable mount aliases between final
admission and the held-parent operation. Existing reviewed owners may continue
child work only under the exact already closed controls, with repeated
pidfd/birth scans covering current children; any unclassified new PID blocks
unlink. Do not signal or suspend another owner to manufacture a quiet scan.
Defer retirement if the live closure cannot be completed while jobs continue.
An unrelated later process is not covered by an earlier point-in-time scan.

## Stream, independently audit, then persist separately

Root may stream this one at-most1GiB logical member through a separately
reviewed bounded owner in the exact current64GiB/swap0 cgroup, with512MiB self
RSS,1MiB chunks, unchanged deadlines and8GiB active backing floor. No second
source body or archive is written to Linux backing. The exact archived member
set is one relative name; report/ledger originals are not moved. Record the
source mode/uid/gid/time metadata in the audit manifest and hash every member
byte plus the complete compressed stream.

The initial receiver may use a fresh Root-selected Mac `/tmp` file. That file
is only staging. Independently verify complete-stream hash/length, complete
gzip termination, exact allowed tar headers/member set, sizes, full body hash,
metadata, no followed links and no unexamined trailing members. Then write a
**separate** Root-selected persistent archive, verify its exact bytes, fsync
the file and its parent directory and reopen its actual full pin. The source
Linux body stays online until all of these are complete. Neither a completed
SSH transfer nor a `/tmp` archive alone authorizes retirement. Destination
capacity and possible temporary/persistent coexistence need actual admission;
compressed size is not predicted from the tar's logical length.

## Held-parent entry retirement, only after all prior proofs

A separate Root-reviewed mutation owner opens every absolute parent with
O_DIRECTORY/O_NOFOLLOW, holds the exact diagnostic parent FD, and reopens
only its `data.tar` entry with O_NOFOLLOW/O_NONBLOCK. Confirm the selected
ordinary nlink1 inode, permissions, complete actual full7 and verified archive
source facts. Recheck all five consumer roles, every other current/future
consumer, active-process absence and current boot/resource guard. No stale
metadata or old report pin substitutes for that final current admission.

Only then may the owner perform the single descriptor-relative
`unlink('data.tar', dir_fd=held_parent)`, fsync the parent, prove the name absent,
reopen the persistent archive and recheck every protected input/report/ledger.
Do not remove the parent or use a wildcard, recursive actor removal, follow a
symlink, lower reserve, signal another owner or alter an old report/status.
Publish a new cold-location/content receipt that keeps original historical
facts separate from the actual archive pin and post-operation observations.

Observe actual backing/image allocation before/after any explicitly owned
Btrfs-only free-block barrier. Logical input size or summed `st_blocks` is not
reported as reclaimed capacity. If any proof fails before unlink, retain the
Linux original and report the precise unclosed condition; the persistent
archive can remain as an additional copy. No source author operation in this
package has performed any of these actual phases.
