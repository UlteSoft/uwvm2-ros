# Same-main typed Unitree command harnesses

This future38 source proposal has not been compiled, initialized or executed. It is maintained test harness code, separate from the fourteen bounded reactor examples. The actual Runtime rejects ROS calls with cross-module ancestry. That guard is intentional and remains unchanged. Giving both a WAT caller and a preloaded application matching aliases cannot authorize such a call. The original private WAT driver is therefore NOT_READY for positive transport and its failed source design remains preserved.

These helpers instead compile into the same actual Wasm module as each real typed example. The actual unchanged initialize/poll/getter/submit/close functions call the actual SDK and actual ROS imports. There is no second Wasm ROS module, ROS mock, hand-written codec or native handle exposed to the Guest. Native UTN1 witness, Gateway, execution gate and DDS remain separately owned native processes. No LowCmd, service, action, firmware address, simulator or performance task is added.

## Fourteen separate command products

`recipes.json` maps every actual reactor recipe to one new command product: Rust, JavaScript, AssemblyScript and TinyGo each GO LowState, HG LowState and API topic RPC, plus API C/C++. Complete GO24/HG11/API8 definitions and actual native identities stay mandatory. A compiler must independently build and validate these fourteen NEW artifacts; it cannot rename a historical reactor artifact or claim transport from compilation. Default and positive runs always use fresh processes and actual externally supplied policies.

C/C++/Rust/embedded JavaScript share `entry.c`. It compiles as a new freestanding C wasm32 object, with exact family1/2/3 and JavaScript0/1 definitions. It links directly with the real scalar symbols in the final module. Embedded JavaScript uses the real generated C symbols `exported_N`: `export_name` changes only the final Wasm label. The compiler derives their exact mapping from the closed ordered scalar export list, checks each actual generated declaration/signature/label and the complete symbol inventory, then gives only the C entry TU literal `-Dinitialize_case=exported_N`-style aliases. Trampoline bodies and the original twelve engine TUs remain unchanged. For Rust the object is passed to the real wasm linker; for JavaScript it is an additional thirteenth TU beside the actual twelve-TU engine/reactor closure. C/C++ retain their real example object and actual C++ termination object. There is no custom C startup runtime: _start is explicitly exported, and no Wasm start section is allowed. C++ example owners are already zero-initialized and have no global constructors. JavaScript is explicitly initialized/status-checked and closed by this entry. All scratch storage is compiler-owned stack/static data in the actual module; no guessed free linear-memory addresses are used.

AS uses `protocol.ts` and one actual lowstate/topic_rpc entry. The owned `selected_case.ts` is only a literal re-export of the exact MF-selected real example, with no replacement function body. A literal selected_family1 or2 is generated for the LowState entry. Compile the actual entry with `--exportStart typed_command_entry`. Its ordinary void export contains real AS runtime/global initialization followed by this finite top-level protocol. Runtime explicitly chooses that actual local export as its main entry. There is no implicit start and no second initialization call. Original real scalar functions remain exported too.

TinyGo uses native Go protocol and selected main source, with the complete actual SDK/example/generated family. In the selected OWNED example copy only, exactly one literal `func main() {}` is replaced by a comment before that copy's first pin. All actual typed function bodies and original source bytes remain unchanged. The separately authored command main supplies the real protocol. The original installed target JSON remains immutable; the new owned copy changes buildmode from c-shared to default and appends the same64MiB max-memory flag. The exact compiler invocation selects default mode, opt1, scheduler none and original supported target tags. Official retained TinyGo runtime_wasmentry.go and scheduler_none.go show that default command startup initializes the runtime and package data then calls main. The reactor _initialize initializes packages only and must not block; it is not reused as a blocking command. Actual _start export/import/start-section behavior still requires real compiler/binary proof. No manual wasm build-tag injection or scheduler/goroutine is introduced.

## Basic I/O and native ordering

All language entries introduce exactly basic WASIp1 fd_read, fd_write and proc_exit. All optional WASI rights remain denied. They neither inherit environment nor open files/sockets. The actual Runtime main alone receives the explicit external aliases in a positive case. Default main policy stays empty. There is no preloaded application and thus no module-crossing ROS call.

The command emits `READY_TYPED_MAIN` before typed case initialization. AS/TinyGo readiness follows their actual language initialization. C readiness precedes embedded JS initialization. The held execution gate and actual main executable must be proved before supplying setup. Parent writes16 bytes: ASCII UTM1, family:u32le (GO1/HG2/API3), mode:u32le (denied0/positive1), reserved:u32le0. These bytes select the test case; they grant no authority. Family is compile-bound and checked. API uses id1/api_id1, LowState uses its actual family/reserved0.

Successful setup emits `TYPED_INITIALIZED MODE`, requiring actual status0/count0 and the correct denied flag. Denied setup must have observed actual alias denial13 through the real example. It checks poll9/close9 and API submit9, emits `TYPED_DENIED_VERIFIED`, waits F, completes real language cleanup and emits `PASS_TYPED_CASE` before proc_exit0. The independent native witness must separately observe no Guest endpoints/payload for at least2sec/30 samples.

Positive API waits S; only then actual submit0/repeat9 occurs and `TYPED_SUBMITTED` is emitted. Native M must first observe the real Request reader and Guest Response subscription. Native A follows submission and waits for the actual lazy Request publisher and complete Request before producing Response. LowState native M precedes P and its one independently observed native publication. For either role, each R triggers exactly one real poll, at most4096 total; idle11 emits `TYPED_AGAIN`. A successful poll requires count1/status0 and emits the same TYPED_STATE all60/105 unsigned binary32 words or TYPED_RPC response-code record used by the external native oracle. The code does not manufacture a successful payload.

C then closes the actual acquired owners, checks close9/poll9 (API submit9), emits `TYPED_CLOSED`, and waits F while native Z verifies real endpoint removal and quiet. All ordinary failures attempt example closes; JavaScript also attempts engine close. First error status stays failure. External owned process cleanup remains mandatory for a trap/panic/kill or failed I/O. Pipe transfers are finite, bounded to16 setup bytes or one control byte and4096 output bytes. Short progress and bounded INTR retry are permitted; EOF, EAGAIN, overrun and zero progress fail. There is no clock/random request, hidden poll loop or middleware retry.

## Reproduce the actual build without a foreign-module wrapper

The SDK [typed example guide](../../../sdk/robots/unitree/TYPED_EXAMPLES.md)
contains the actual messages, alias policy, generated-family staging and
lifecycle. Start with one selected row in
`sdk/robots/unitree/recipes/closedtyped-example-recipes.json`, then the matching
`reactor_id` row in this directory's `recipes.json`. Resolve every tool,
complete generated family and source path from pinned operator inputs. Use a
fresh output per product. The original installed SDK, generated family and
reactor artifact stay read-only. Do not expand arbitrary flags or run an
unreviewed build plugin.

For C, C++, Rust and JavaScript, compile `entry.c` with the *same actual WASI
compiler/sysroot family* as the selected recipe, using the following token
shape (`$...` here denotes an explicitly selected pinned build input, not an
implicit search or a value supplied by the Guest):

```sh
"$WASI_CLANG" --driver-mode=gcc --target=wasm32-unknown-unknown \
  --sysroot="$WASI_SYSROOT" -std=c11 -O1 -g0 -UNDEBUG \
  -ffreestanding -fno-builtin -fno-fast-math -ffp-contract=off \
  -DUWVM_TYPED_FAMILY=1 -DUWVM_TYPED_JAVASCRIPT=0 \
  -MD -MF "$OUT/command-entry.d" -MT "$OUT/command-entry.o" \
  -c "$SOURCE/tests/ros_unitree/typed_command/entry.c" \
  -o "$OUT/command-entry.o"
```

Select family1 GO,2 HG or3 API. JavaScript selects `UWVM_TYPED_JAVASCRIPT=1`
and additionally needs the entry-only generated C-symbol aliases described
above. The three JS rows all use unsigned scalar signatures; reject a changed
signature rather than guessing a C declaration. Produce the original actual
example object, Rust rlib/module or twelve engine objects according to its
real recipe. Link this new entry object directly into that same final module
with explicit `_start` export and no entry/start section. For Rust, pass
`-C link-arg=/absolute/command-entry.o -C link-arg=--export=_start` to the actual
Rust link invocation, retaining its actual wasm-ld trace. Do not change the
real SDK function names or use a preload import to satisfy them.

C/C++ keep full original `-MD/-MF/-MT` compile evidence and linker trace.
C++ keeps the matching independently qualified official termination object
before its archives, strict assertions and the actual extraction proof.
JavaScript first runs the maintained `sdk/javascript/guest/prepare.py` with
the complete closed manifest, then follows all twelve real compile jobs
unchanged. Preserve its original allow-symbols file; a separate command-only
file contains exactly those bytes plus `exit_process\n`. Its actual derived
link adds only the fresh entry object, the selected fresh allow file and
`--export=_start`. No unresolved scalar function or optional WASI symbol may
be waived. Keep every actual preparation/source/object/archive/trace pin.

For AS, copy the real SDK, complete generated family and actual selected
example at their original source-relative paths. This directory's shared
`protocol.ts` and selected AS entry are the actual compile entry. Generate a
literal `selected_case.ts` that only re-exports the exact original export
names from that selected example; LowState also gets a literal
`SELECTED_FAMILY:u32=1` or2. Keep all real typed bodies unchanged. Replace only
the original recipe entry source and `--exportStart _initialize` with
`--exportStart typed_command_entry`. The exported runtime initializer executes
the finite top-level command after language/global initialization. Preserve
actual original scalar exports and validate the actual local entry.

For TinyGo, copy the complete SDK/example/generated family into a new owned
module tree. In only the selected owned example, replace exactly the one
empty `func main() {}` with a comment, then add `protocol.go` and the selected
`command_lowstate.go` or `command_topic_rpc.go` as real same-package source.
Preserve all other example bytes. Derive a separate owned JSON from the
pinned self-contained `wasm-unknown.json`, changing only `buildmode` to
`default` and appending `--max-memory=67108864`. Change the original actual
compiler's `-buildmode=c-shared` token to `-buildmode=default`, retain opt1,
scheduler-none, backend/family tags, offline SDK packages and fresh caches.
Use the target's real `tinygo.wasm` platform tag; never inject `wasm` manually.
No original SDK target or example is edited. The resulting `_start` must be
proved from the actual binary, not asserted from target JSON.

For every language, run the selected real full Wasm validator and retain its
actual exit/log. Independently read the entire binary table. Require only
real backend2 ABI imports and exactly basic fd_read/fd_write/proc_exit with
their actual signatures, no implicit start, no imported global/memory, one
own memory with maximum1024 pages, and the original complete scalar exports.
The explicit command entry must be a local `()->()` function. When Runtime
uses `--wasm-set-start-func`, its argument is the *local-defined index*, so
subtract the actual function-import count from the entry's absolute binary
function index. An export index cannot be passed blindly. The owner must also
prove the actual Worker binary and main principal before releasing setup.

The private Root compiler adapter is a convenience for constructing these
same actual commands under the repository's complete source/whole-root/pidfd
receipts. It does not replace this SDK contract, confer authority or install
anything. Its future actual source MF and every physical input must be
selected after publication. Merely possessing this source tree, a recipe or
a previous reactor build is insufficient to launch a positive case.
